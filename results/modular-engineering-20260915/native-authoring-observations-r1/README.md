# 同一 TRAIN 材料任务的两次独立观察

两次请求分别预留一次 MAIN 调用，冻结上限均为 8,192 输出 tokens、
131,072 总 tokens、240 秒、零重试。任务、引用材料、类别和输出模式一致。
第二次明确选择低推理档，并修正空白对照的来源标记指令。

| 观察 | 原生进程 | 输出 tokens（含推理） | 原始结果 |
| --- | --- | --- | --- |
| r2，源码 `50f1611d` | 240 秒超时；记录到正常结束事件 | 8,666（推理 7,004） | 拒绝：超过输出上限；另有空白对照来源标记错误 |
| low-effort-r1，源码 `725a351f` | 45.159 秒；正常退出 | 1,769（推理 561） | 格式和精确摘录通过；6 类 ready、2 类缺依据、1 类不适用 |

第二次仅取得临时作者材料，没有准入正式材料、独立评审或校准。
这两次改变了生成指令和推理档，不能分别估计二者的因果效果；单次较快
也不是稳定性能收益或 benchmark 效果。第一份失败结果保持不变。

第一份记录的模型结束约在监督器截止前 6.5 秒；关闭阶段临近截止。
证据不足以把超时归因于某个具体退出或管道问题。配置、目录键和调试中
的请求上限均已核查，实际超限原因仍未确定。第二次未超限不证明服务端
必然执行该上限。

每次均观察到 1 次 MAIN、3 份空工具清单、0 次工具调用；全部输入只来自
冻结 TRAIN 引用。现有订阅账户前后观察均剩余 72%，按需额度、使用和预付
余额为零，自动充值关闭。服务端报价分别为 $0.01978188 和 $0.00575552，
不是追加扣费证明；标题调用、总机会用量和最终结算仍记为未知。

`manifest.json` 对应本次封存文件；`comparison.json` 对原始私有请求、事件流、
调试日志和响应提供摘要与本机引用。两份 envelope/reservation、观察脚本、
配置、固定字段时间线、59 项传输检查与 40 项生成流程检查的源码快照和 JUnit
原件可在本目录核对。原始模型内容和账户凭据未复制到公共证据目录。

`r2/counterfactual-format-check.json` 仅记录离线格式诊断：在内存副本中将空白
对照的 provenance 改为 controlled_hypothetical 后通过原验证器。它没有改写
原模型输出、放宽验证器或把 r2 改判为通过。实际源码只澄清后续生成指令。
