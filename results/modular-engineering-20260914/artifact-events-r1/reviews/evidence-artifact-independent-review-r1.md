# Independent review: M1/M2 event-to-artifact bridge (r1)

Scope: read-only review of integration `98eae28` plus the in-progress callback edit in `modules/evidence.py`. No algorithms were changed.

1. **[P1] Keep the bridge's durable ordering explicit.** `_JsonlLog._append` correctly calls its sink only after `flush` + `fsync` (`modules/evidence.py:95-105`). The bridge must emit one immutable descriptor for *every* persisted evidence/claim event from that callback, including `withdraw`, `dependency_update`, `summary_notice`, `withdrawal_refresh`, and `dependency_refresh` (`modules/evidence.py:324-350, 393-395, 440-480`). Attach the raw frozen event as payload and chain each bridge descriptor to its immediately preceding bridge descriptor (and, for a claim relation, to the referenced evidence bridge descriptor where available). Do not reconstruct a current snapshot: it loses propagated-claim order and the visible durable-gap semantics.

2. **[P1] Failure must reach a terminal, durable run state.** Ledger mutation occurs before `_log.append` (`modules/evidence.py:249-263, 411-443`), while a sink failure happens after the source JSONL row is durable. A callback `on_failure` that merely sets `session._terminal` leaves the trace non-terminal (`runtime.py:475-490`), and `full_loo_driver` then cannot call `controller_failure` because that method rejects terminal sessions (`runtime.py:404-414`; `full_loo_driver.py:120-127`). Make the callback failure path write a minimal fsynced failure marker/trace entry without re-entering the catalogue, latch terminal, and re-raise. The replay verifier should reject an unsealed/gapped bridge rather than treating the durable ledger row as a normal completed run.

3. **[P1] Verify bridge semantics through public ledger replay, not catalogue hashes.** `verify_stage` currently verifies the catalogue and only compares its `trace_event` payloads to `trace.jsonl` (`full_loo_driver.py:172-182`); it rebuilds M1/M2 with `_MemoryLog` from operational inputs (`full_loo_driver.py:200-202, 266-267`). A rehashed artefact descriptor can therefore remain syntactically valid without proving that its payload is a ledger event or that claim propagation is replayable. Add a separate verification seam that constructs `EvidenceLedger(identity, storage_path=evidence.jsonl)` and `ClaimLedger(evidence, storage_path=claims.jsonl)`, uses their public `snapshot`/`claims`/`roots` views, and checks a one-to-one ordered correspondence between those journal events and the M1/M2 bridge descriptors. Include tamper-and-rehash tests for an evidence row, a claim refresh row, and a missing/extra bridge descriptor.

4. **[P2] Preserve disabled-arm meaning.** The live session creates both ledgers unconditionally (`runtime.py:249-250`), and `admit` can append evidence regardless of the M1/M2 flags (`runtime.py:416-442`). A bridge that labels every such descriptor `M1`/`M2` as `produced` would falsely report an enabled module on baseline/disabled cells. Derive descriptor status from the frozen `arm.enabled`: use `produced` only for the enabled owner module and `not_applied` otherwise; retain payload and `scientific_validated=False`. The verifier should assert this mapping.

5. **[P2] State the production scope or cover the second persistent caller.** `RunSession` is the main persistent pair (`runtime.py:249-250`), but `retrieval_stage_panel_drivers.py:138` also makes a persisted `EvidenceLedger` with no bridge. If C4 artefact coverage claims all M1/M2 durable ledgers, it is incomplete. Either wire that caller too, or explicitly constrain the bridge and verification to `RunSession`'s `runtime/evidence.jsonl` and `runtime/claims.jsonl`.
