# M3 context artifact independent review (f5eb91f)

Read-only review of `f5eb91f75e1d02b5c693303e729184ee8981c663` atop `c2dcffc`.

1. **[P1] `verify_stage` validates every historical request with one final snapshot, not the snapshot available at that `invoke`.** `RunSession.invoke` captures `evidence_snapshot` and `claims_snapshot` immediately before each request (`runtime.py:351-359`). In contrast, `full_loo_driver.verify_stage` reconstructs transition state once (`full_loo_driver.py:201-203`) and passes its final `evidence.snapshot()` / `claims.snapshot()` to every artifact (`:204-205`); `verify_session_context_artifacts` supplies those same objects to each `verify_context_artifact` (`context_artifact.py:130-131`). Thus a valid first request before an append/withdrawal/claim refresh will fail once a later request changes the ledger; worse, the verifier has no independent record of the historical prefix to distinguish it from a forged stored snapshot. Fix by recording, at each invocation and before the model request, immutable ledger-prefix bindings (for example ordered evidence/claim journal head or count plus the exact snapshots) in the trace, then rebuild those prefixes through public ledger replay and compare them one-to-one to each M3 artifact. Do not use a final snapshot as a substitute.

2. **[P1] The projection relation is recorded but never recomputed or independently bound to a known projector.** Runtime records `controller_context` and `public_context` (`runtime.py:337-342`), but replay only checks that the recorded public value equals the request (`context_artifact.py:118-123`). It never derives public context from controller context; `verify_context_artifact` likewise accepts the stored `before_projection` and final request context (`:48-53`). A coordinated trace/artifact rehash can therefore replace both sides with an arbitrary projection while preserving all M3-local equalities. Give the verifier a frozen, versioned projection contract (or a pure reconstruction function plus its source/config reference) and apply it to the trace's controller context. Bind the resulting public context to the request; reject a trace projection row that cannot be recomputed.

3. **[P2] Trace-to-projection correspondence is incomplete.** Request-to-artifact coverage is one-to-one (`context_artifact.py:94-108, 133-134`), but `q8_public_evidence_context` rows are only indexed by slot. Extra rows for unused slots are accepted; a projection row is not required for every projected request; and the loop finds the first prior same-slot row rather than enforcing the immediately preceding causal row (`:77-85, 118-123`). Validate exact counts and require each projection row to be immediately followed by its same-slot `model_request` (allowing only explicitly documented intermediary stages), with no orphan rows.

4. **[P2] The stage verifier does not assert the M3 descriptor producer source.** The unit test checks a `runtime.py` suffix (`tests/test_m3_context_artifact.py:42`), while the actual verifier checks module, coverage, status, task/budget/lock, and payload only (`context_artifact.py:101-114`). `ArtifactCatalogue.verify` validates whichever producer source is stored, not that an M3 context artifact came from the M3 runtime seam. In `verify_session_context_artifacts`, require `descriptor['producer_source'] == source_snapshot(runtime.py)` (or an explicit frozen M3 producer reference) so a rehashed descriptor cannot claim a different producer.

5. **[P2] The rehash test does not cover the public replay entrypoint.** `test_rehashed_m3_payload_cannot_pass_trace_catalogue_replay` calls `verify_session_context_artifacts` directly with an in-memory `RehashedCatalogue` (`tests/test_m3_context_artifact.py:81-101`). It never invokes `full_loo_driver.verify_stage`, never rewrites the actual trace/catalogue/seal/receipt sequence, and changes only an artifact payload while passing the correct final snapshots. Add an end-to-end C4 fixture that mutates an earlier context or projection, recomputes local hashes/catalogue entries/seal as the attacker would, and proves `verify_stage` rejects it through the new historical-prefix and projection-reconstruction checks.
