# C4 full and leave-one-out execution checkpoint

`run_full_loo_train` in `research_loop/modular/full_loo_controller.py` executes
the explicit C4 panel through real module operations, restricted candidate
builders, Docker and an independent scorer process. The verified scope uses
synthetic model responses, source authorities and scorer references on two
synthetic primary TRAIN tasks. It establishes an executable engineering seam;
it does not establish scientific effectiveness or complete C1-C5.

## Frozen intervention and resource allocation

The prospective `c4-full-loo-composition-v2` recipe retains full F, all nine
requested removals, B0 and a useful ordinary control. Removing M2 while keeping
M3 and M9 is structurally unavailable, with both dependencies preserved. There
are 22 executable target cells and two structural rows. The runtime also binds
the identities of all 48 original issue contracts; that inventory does not
claim new execution coverage for each issue.

M1-M7 operate in both fixed-history/build and target stages. A legal removal
clears every declared use. M8 operates only in targets, so F versus without-M8
is conditional on the same full-history candidate. M9 operates only on the
fixed TRAIN history; its comparison changes candidate selection and retains
the common target solve. No target observation, future measurement or scorer
output is admitted to the history optimizer. Every candidate freezes before
the first target executes, and all target provider ledgers seal before scorer
startup or RPC.

Candidate sharing requires identical history inputs, builder, model/context
budget, factor levels, candidate procedure and operation bindings. F shares
with without-M8; B0 shares with the ordinary control. These are nine unique
canonical builds, each with five model slots. Each full, legal LOO or ordinary
target has six model slots. B0 has two solver slots and is explicitly unequal
to F. The strong ordinary control has useful planning, two sequential critiques,
retrieval, selected auxiliary execution and revision. Its second critique sees
the first response. M5-on instead seals two independent responses before
reveal. This distinction is declared in the v2 operation bindings.

## Executable API and boundaries

Construct `FrozenFullLooRuntimePlan` from a frozen composition, original
`FrozenTrainHistory` and public history CSV binding, exact target identities and
CSV hashes, parent package, restricted builder version, admission/retrieval and
exploration/scheduler materials, independent authority bindings, model schemas
and budget, scorer bindings, objective and pinned image. Its validator rejects
overlap with history, changed public inputs, missing issue IDs, incompatible
material subjects or allocations. `tests/test_full_loo_runtime.py::prepare`
contains a complete synthetic construction; runtime code has no test import.

Call `run_full_loo_train(plan, ...)` with the prospective exporter, fresh snapshot,
export and run roots, model and retrieval ports, independent state/corpus
verifiers, audit verifier, execution authority and scorer factory. The factory
receives the frozen `FullLooPanel` and must return the exact
`CombinationScorerProcessClient(full_loo=True)` with matching panel, authority,
reference-handle and scorer configuration. The owning process config is
`c4-full-loo-scorer-process-config-v1`. This scope is mutually exclusive with
the existing execution-improvement and other combination scopes; those panels
are not relabelled as C4.

The controller owns cleanup of the returned scorer client on success and
failure. Factory or configuration rejection leaves 22 charged execution rows
with blocked scoring, records the startup attempt, and permits no scorer RPC.
Known per-cell execution/scoring failures retain their denominators; failed
builds or unknown costs block targets. Source preflight errors persist reserved
rows in `attempts.json` and raise before the terminal receipt path.

`verify_full_loo_cell` replays original exported CSVs, the candidate barrier,
provider requests/responses and native admission, evidence, lineage, prediction,
review, retrieval and scheduling artifacts. M4 freezes before fresh auxiliary
measurement; M5-on reviews reveal only after both seals. Model choices reach
actual selected Docker jobs and all composed outputs reach the common solver.
Docker replay checks the exact pinned image, mounts and restricted command.
The independent scorer receives signed sealed execution projections through
its own process and private synthetic reference store.

The new execution contract requires composition v2. Historical v1 freezes are
read-only accepted with either historically possible single dependency reason;
they are not silently rewritten or executed through the new contract. V2 uses
the complete deterministic reason, avoiding cross-process hash-seed drift.

43 tests, with all 553 tracked Python/Markdown source files unchanged during
each check at source commit `47d0200` and zero paid calls.

The frozen tests execute the 22-cell grid and independently verify native

Original CSV and barrier replacement fail replay. Durable whole-package rollback
is checked using the actual composed candidate with an explicitly synthetic
host validation authority, including reopening deployment state.

The companion shared checks cover queue leases/dependencies/resource conflicts,
actual overlap, timeouts and cleanup, atomic claims, existing scope compatibility,
and deployment/rollback guards. Frozen closures and original artifacts are in
`results/modular-engineering-20260913/full-loo-c4/runtime-v2/`. The manifest binds
archive bytes and each archived original to its SHA-256. Original failed attempts
remain in the bundle; repairs do not replace their closures. Host absolute paths
remain provenance fields. Archive integrity is not independent hostile-host
attestation, and synthetic scorer results are not scientific measurements.

## Remaining qualifications

P0 remains mandatory. Every solver finishes through `RunSession.finish`; this
checkpoint records `scientific_execution_qualified=false` and
`promotion_allowed=false`. It is not a P0-qualified scientific run. Each paired
contrast retains its own changed components and null confidence interval;
unrestricted nine-factor interactions are not identified by this design.

This version requires the existing **CodexModelPort** contract, frozen to
`gpt-5.6-luna` at low effort. The separate `GrokTrainModelPort` and the default
Grok entry point are **not supported by C4 v2**. Provider-neutral output, cost
and replay contracts and an actual default-entry synthetic integration need a
separate versioned extension. No real Grok or other paid model invocation was
performed here.

Train selection of a final bundle and independent validation acceptance remain
the separate C5 obligation. Q6.3 remains a separate metaprogram phase. No real
benchmark references or validation capability were opened for this checkpoint.
