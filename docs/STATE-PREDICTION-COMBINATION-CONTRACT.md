# State plus prediction train combinations

Scope is limited to `pair:M1+M4`, `pair:M2+M4`, and `pair:M3+M4`.  Each
registered conditional factorial retains its four legal cells; `M3` uses the
registered fixed `M2` background.  This document freezes the engineering
contract before any model or Docker execution.  It does not add a result for
the remaining pairs, triples, full bundle, or leave-one-out obligations.

Every cell is TRAIN-only and consumes one same-schema public prediction
proposal, analysis-program, and final-answer opportunity; one Docker attempt;
two exact-material authority calls; and one independently issued scorer input.
Failures, unknown source cost, or malformed provider output close that cell and
remain in its denominator.  Validation is never opened by this family and
singleton outcomes never remove a legal cell.

The driver first performs the existing subject-bound transition.  M1 uses
`FrozenAdmissionMaterial` plus `AdmissionMaterialVerifier`; M2/M3 use
`FrozenLineageMaterial` plus `DualMaterialVerifier`.  It then passes the
resulting public state to the actual `PredictionRegistry`: M4-on freezes the
returned competing plan before the shared solver can invoke Docker.  M4-off
still obtains the same ordinary proposal and supplies it to the solver, but
does not register it.  Thus all matched slots have useful downstream input.

For M1+M4 with M2 off, the transition's ordinary buffer filters the public
projection by M1's current before/after admission decisions.  The M4 request
therefore receives qualified/raw public observations and public context even
though no evidence ledger is enabled.  Authority names, verdicts, arm labels,
and scientific truth are excluded from requests.  An execution success is
only an engineering receipt and can never become scientific evidence.

Independent scoring is outside this narrow driver: callers must issue the
score only from its replayed runtime, using the established independent scorer
process and frozen scorer handle.  Synthetic fixtures may exercise this seam;
they do not measure scientific utility or validation acceptance.

For the M1 contrast, the controller must retain one frozen, signed
before/after qualification snapshot per comparable task/replicate, or run the
semantic qualification-parity gate before contrast estimation.  The gate
compares precisely the assessments consumed by `EvidenceAdmission`, excluding
cell signatures.  If they differ, all cells, costs, failures, and scores stay
in the receipt but that contrast is `inconclusive`.  M2/M3 provenance
qualification only establishes frozen-material acceptance and is not treated
as the same semantic state.
