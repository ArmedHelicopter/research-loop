# Q3.2 实际执行产物

2026-09-15。此契约覆盖 Q32ExecutionStage 的联合/分别两种方案，以及旧入口和
native prospective panel 的实际返回与消费关口。M4 是这项比较的固定背景；
审计接入不改变四个模型槽位、三个执行机会、FIFO 或 TRAIN 数据范围。

每个运行沿用 RunSession 在模块操作之前建立的唯一 run ID、任务锁、
代码来源及配置。PredictionRegistry 的实际持久化事件立即登记到产物目录。
联合方案只冻结一个计划，然后将三个预分配测量绑定到该计划；分别方案冻结
三个计划。原先联合方案重复冻结同一个 plan ID 会在构造阶段报错，此处修复
了该错误。编译器的无磁盘 registry 只是输入检查，不作为独立运行产物计数。

`q32_output` 描述符保留实际计划、每次公共请求、三个程序的完整封存、执行绑定、
观察、比较输入、失败及最终结果。程序封存引用真实模型返回；观察引用执行绑定
和原执行回执；比较和结果引用此前的观察。所有关系还绑定原 trace 的所在位置。
预测日志不得增加 outcome 事件：数值处于声明范围不构成科学证据资格。

每次模型或执行调用前重新读取磁盘前缀，检查任务/编译/单元/run ID、预测事件、
逐项描述符及已产生程序的实际字节。`execution-seal.json`、`result.json` 使用
独占写入和 fsync，最终 `q32-artifacts-seal.json` 绑定完整文件清单及目录封存。
下游 `verify_q32_execution` 同时检查原执行语义和上述产物契约。

native panel 在开启下一个单元前、最终汇总前重新核验所有先前完成的单元。
若后续单元期间发生早期产物漂移，历史调用和测量仍保留，整轮失去评分资格，
剩余单元保留为未执行。构造/终态存储异常也保留四单元、十二测量的分母；
已经消耗的机会不得改为零。已完成写入后交付失败保留原文件和失败标记。

读取器不创建/触碰日志，不调用模型、Docker 或评审器。它拒绝路径及祖先中的
符号链接/目录联接、截断、遗漏、额外文件、不相符的来源和失效的依赖关系。
`inventory` 仅用于对保留字节作存储盘点；存在 audit-failure、缺少封存或部分
写入的前缀不能获得完整验收。若磁盘连独立失败标记都写不下，只保留已有字节
和上层失败状态，不生成虚假的完整失败证明。并发外部写入的原子快照/操作系统
权限隔离不在此文件级检查的保证内。

本次读取器要求记录中的原始代码路径及字节仍可解析；历史源码迁移解析尚未
接入此宿主。旧版裸 trace 应按其冻结的旧代码回查，不能自动升级为本契约的
完整产物。可重算的哈希链用于一致性及来源关系核验，不是抵抗整体替换的外部
身份签名。模型提供方原始调用仍由原有 provider ledger 负责核验。

工程检查、合成模型和实际 Docker 只证明对应执行路径；真实模型效果、独立
科学评审、全部单模块与组合实验，以及 VAL 验收仍分别要求原定证据。
