# 调查：何种「比裸 agent 有效」对照合法

时间：2026-08-27。目的：在不改 `docs/SPEC.md` 四条判定规则、不占用 Zheng et al. / AIDE / AI Scientist 的前提下，找到一个可执行、可证伪的有效性定义并跑完。

## 现状

- **n=40 已经是「对裸 agent」。** 臂 A 单会话，臂 B 先锁规则再观察。主终点协议违规未支持，判别力跌破非劣效界。见 `docs/VERDICT.md`。同一题集上再按题型事后切片，是见结果后选子集，不合法。
- **整机 L001** 两次四事件皆 1，无裸 agent 对照，不能当「比裸 agent 有效」。
- **纠错切片题全是已知缺陷。** 全判 `invalid` 也能「捕获」。无干净记录则无法挡 H_ceremony。
- **对已有开源/闭源项目。** FOREAGENT 占据 AutoML 执行前方案筛选；AIDE / AutoMind / MLEvolve 占据 Generate-Execute-Feedback；AI Scientist 占据自动写论文。任务、终点、预算都无法与本仓科研决策记录匹配。把 Beat Ratio 或论文产出当本协议分数，是占用别人的构念。

## 仍开放、且能在本仓执行的

对**已经写成**的决策记录做二元审计：记录有的该拦、有的该放。对照是同一模型、同一记录、同一解码的单 agent（裸），干预是协议审计臂（角色约束 + 预注册清单 + 不得改规则）。

这与 n=40 不同：n=40 问的是见结果前锁字符串能否少违规；本题问的是**事后审计已写记录**是否比无角色约束的单次判定更准。

## 关键约束

- 必须混合已知应拦与已知应放，否则过拒与捕获不可分。
- 必须在阅读任何本题 scored aggregate 之前冻结判定规则。
- 不得回写 `docs/SPEC.md`。即使本题阳性，n=40 的 H_protocol 仍是未支持。
- 不得使用源仓 PSB 原题或 `gate.json` 里的判定。

## 调查结论

- 现状是：整机有效性仍未知；锁字符串对裸 agent 的确认性对照未支持。
- 关键约束是：新对照必须换 estimand，不能在 T001–T040 上翻案，不能拿 FOREAGENT 当基线。
- 之前不知道、现在知道的是：现成纠错题全是坏记录，不能直接拿来当「比裸 agent 有效」的确认性题集。
- 基于以上，判断是：合法方案是冻结一份混合已写记录的审计对照（n=16），先写 SPEC 再跑模型。
