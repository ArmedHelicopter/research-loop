# Common C5 TRAIN comparison precommit

`FrozenJointTrainProtocol` freezes a new common-procedure candidate catalogue
before TRAIN execution. C1, C2, C3 and C4 originally use different procedures,
budgets and estimands. Their raw scores cannot be pooled to choose a C5 winner.
`trial_binding()` binds the complete protocol digest, recipe, target and
replicate. Bare recipe aliases cannot key build or result reuse across locks:
component configurations, provider or scorer changes produce a different lock.

The catalogue includes the union of all legal settings in the nine conditional
singleton designs, 36 pair designs, five triple designs and full/leave-one-out
design. All structural exclusions retain their origin and exact missing
prerequisites. Only identical complete generated recipes share aliases. These
are **new compositions**, not the original source candidates: an alias records
the factor setting that motivated a new common comparison. Different original
Q variants, configurations, histories, packages and procedures are not claimed
identical, evaluated again or completed by this projection.

Every matched candidate uses the same five history and six target model slots,
context allocation, provider contract and scorer configuration. M9 selects on
history only; M8 affects target scheduling only. B0 retains its two target slots
as a separately reported reference and is excluded from matched-budget ranking.
The selection rule freezes its complete tie order and thresholds. No observed
scores are accepted by this interface, and negative singleton results cannot
remove a setting. Group means then benchmark means are the existing TRAIN
selection rule; they are not statistical acceptance or interaction estimates.

The lock binds public task/CSV bytes, a shared TRAIN split, all nine separately
versioned component templates and explicit runtime source bytes. History and
target groups cannot overlap. It supports more than two target tasks while
requiring both primary benchmarks. All 48 complete issue contracts, including
their variants and separate Q6.3 obligation, remain in the lock. Original byte
checks run before an exclusive lock write and can be repeated independently.

This is an executable **precommit and input-verification seam**. It does not
produce history builds, prove source-manifest completeness, run model or Docker
cells, authenticate old scores, choose a winner, lease validation data or grant
acceptance/deployment. Those capabilities remain false. The common runtime must
still bind actual frozen materials, scorer handles, independent qualifications,
builder originals and component consumers before starting. It must execute the
full common grid, authenticate its original results, preserve failed/blocked
denominators and apply the precommitted rule. No old C4 schema or controller was
loosened to make this larger grid appear executable.

The tests exercise the real catalogue compiler, public-input/source verifier,
provider-configuration validator and exclusive disk-lock writer with synthetic
TRAIN inputs. They provide engineering evidence for this boundary only.
