# Private four-task material authoring

`evaluation.modular.diagnostic_material_authoring` prepares provisional materials
for the existing four exported TRAIN tasks. It never gives author assertions
known expected rubric scores. The previous HTTP monetary manifest, native smoke
contracts and receipts, and diagnostic180-main allocation retain their meaning.

The separately versioned authoring envelope permits at most four main prompts
and four possible initial title opportunities. Both select grok-4.6. Each main
requests8192 output tokens; each initial title has100. Retry count is zero,
complete prompt limit262144 UTF-8 bytes, observed main total limit131072, and the
native session lifetime remains60 seconds. These limits are request and observed
accounting bounds, not measured tokenization or a context-capacity guarantee.
Before each prompt, native ACP requires a freshly verified included-only billing
and no-topup state plus the selected model and same-session public tools `[]`.
It persists a reservation before prompt I/O and owns the subprocess tree.

The preparation worker resolves complete task and reference bodies. `freeze`
compiles all four prompts and output schemas with publication, implementation,
configuration, reference and opportunity pins before any native dispatch.
`provision_native` only writes private keys/configuration and opaquely copies the
already-authorized local login into four fresh runtime homes; it launches no
executable, reads no auth body, and never places auth bytes or hashes in evidence.
Each native home/profile/cwd is distinct. `run` reconstructs all four complete
requests and checks all fresh native contexts before opening the first session.
An envelope has one exclusive durable run reservation and cannot be resumed or
retried, including after a rejected or unknown main outcome.

Every response is bound to its original native observer receipt, actual prompt,
schema, response digest, session/prompt reservation and complete source manifest
before material signing. The shared binding helper retains the original bridge
semantics. Native faults, unknown/incomplete main usage, account changes, binding
faults and source drift stop later authoring. Original private ACP streams and
receipts remain available. Valid reported main usage is retained on rejection;
title usage, all-opportunity tokens/cost and final settlement remain unknown when
unreported. Main `modelCalls=1` is never relabelled as the total model-call count.

All four planned authoring states,36 category slots and72 evaluator opportunities
remain represented. Candidates are anonymous answer mappings. Unsupported
negative findings and alternatives stay unresolved/not applicable. A negative
cannot be justified solely by nonsignificance or an incorrect answer. Ready
positive/negative/alternative rows require reference provenance with exact source
excerpts; this mechanical binding does not certify their interpretation. An
empty-output ready answer is literally an empty string. Controlled hypothetical
corruptions carry private provenance and do not claim benchmark execution.

The worker signs separate private support records and materials. Every material
has expected state `unknown` and null dimensions, including unavailable slots.
Author signatures establish source/candidate/support bindings, not expert truth.
The output reports exact availability counts; slot existence is not scientific
coverage. Independent diagnostic review still occurs later, and same-model
review does not establish physical independence.

After authoring, the worker compiles every ready review/evaluator request through
the existing private renderer without truncation. The prospective role limits
are explicitly frozen at2048 output tokens,262144 input bytes,131072 observed
main tokens,100 title tokens and60 seconds per native session. The full180-main
review/arbitration/evaluator allocation is separate from authoring's4+4. This
preparation does not dispatch any review/evaluator request or make the result
eligible for calibration, validation or scientific claims.

Private config/envelope descriptors use absolute paths and SHA-256. The CLI
accepts `freeze` or `run`, `--input`, `--sha256` and `--output-directory` and emits
only fixed status/count/hash metadata. Reference, candidate, rationale, raw ACP
and key files stay outside source control and public archives. Actual authoring
follows a review of the clean source/checks and four frozen request metadata
records; initial integration tests use synthetic references and Python ACP peers.

The synthetic child launcher binds its own checkout PYTHONPATH, regardless of
the caller environment. The four-session fixture worker has a separate180-second
parent bound under existing process-tree ownership. This does not extend the
production60-second native lifetime. Tests cover the authoring-to-material-to-
renderer seam, source/candidate/reservation swaps, partial/unknown accounting,
account/tool denial, late-entry preflight failure, complete large references,
provisional support rules and fixed denominators. Fixture success does not prove
the real author's semantic quality or future quota availability.
