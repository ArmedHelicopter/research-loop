# 九组件部署、回滚与任务快照的产物

2026-09-14。`JointDeploymentStore` 的实际 SQLite 写入入口现在同步登记产物。
这套记录描述已发生的配置操作，不生成验收授权，也不替代 C5 的独立验收。

每次 bootstrap、activate、rollback 或 run_task 都先提交唯一尝试编号及输入，
保留完整配置、九个组件摘要、全部 TRAIN 来源、原授权凭据和实际生产方法的
源码快照。配置主体使用 `JointBundleSubject`，不会任意挑一条训练题充当所属任务。
任务记录另绑定实际任务身份和调用前已固定的完整配置。

组件、活动指针、一次性授权消费和成功事件在同一事务提交。组件写入中途失败时，
事务恢复原活动配置，失败事件保留按实际顺序观察到的未提交组件字节、摘要、大小
及写入方法。新的重试有新的尝试编号，不覆盖旧记录。失败日志本身写入失败时，
原始 started 前缀留下未完成尝试；不得宣称已完整记录或操作成功。

任务返回后再发生源代码校验失败，原返回值仍保留，并绑定原任务和配置。事务已经
提交、只在向调用方交付结果时报错时，保留 committed 事实，不追加虚假的失败切换。
回滚恢复原来的整个配置，旧组件记录和验收授权的消费记录保持可查。

`committed` 只说明本地事务已提交，不证明外部调用方已经收到回执或任意外部服务
已经切换。现有 acknowledgement 和任务返回格式保持不变；独立审计锚点通过
`last_operation_receipt` / `artifact_checkpoint()` 获取，调用方的传输日志另行保留。

`deployment_audit_meta` 保存存储身份及任务域，`deployment_audit_events` 保存
规范事件、前项摘要和 SQL 状态快照，`deployment_audit_head` 固定当前尾部。
成功的组件清单必须完整；失败的组件观察必须是实际顺序的前缀。读取器重建状态
变更，核对原授权签名、一次性消费、配置/任务/返回值、生产源码和实际 SQL 行，
而不只是检查摘要链。

调用方应在操作后将 `last_operation_receipt` 或 `artifact_checkpoint()` 返回的
检查点保存到数据库之外。`verify_joint_deployment_artifacts` 要求该检查点、
明确任务域、原授权验证密钥和调用方提供的组件源码根目录；它通过只读 SQLite
连接检查数据库，并重读声明的组件源码字节。旧检查点可以验证保持原前缀的合法
后续追加。修改整个数据库和全部外部锚点的宿主不在此完整性保证内。

历史生产代码可用 `ArchivedSourceResolver` 指向独立固定摘要的源码 ZIP。
这会检查原始源码快照，并不会执行历史代码或重跑模型。继续写入代码版本已经
变化的旧审计存储需要显式迁移，本次不自动替换旧来源。

TRAIN 和 VAL 的任务结果使用不同数据库，`task_domain` 默认是 TRAIN。读取器
和重新打开存储时先检查域头，再读事件与任务内容。完整部署审计包含 V_final
授权信息，所以两种域的完整报告都固定为 `optimizer_visible=False`；优化器
不能把审计报告当作 TRAIN 输入。普通任务仍只消费冻结组件配置，实际 RunSession
检查确认验收授权字段没有进入这条模型调用路径。域检查不代替操作系统权限隔离。

没有旧审计日志的存储只登记当下可见状态，并明确 `history_complete=False`；
不会为过去的部署补造执行记录。旧完整数据库、原回执和失败证据保持原状。
