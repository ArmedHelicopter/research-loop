# 并行实现与组合交互实验

初始规格日期：2026-09-12。当前工程覆盖数、已验证版本及未完成实验统一见 [实施记录](MODULAR-IMPLEMENTATION-STATUS.md)。本补充保留 [原48项实验](MODULAR-RESEARCH-COVERAGE.md)，新增跨模块组合检验；组合总分不能替代逐项机制验收。

## 1. 单模块实验不是组合资格筛选器

没有观察到单模块增益，可能是样本不足、缺少互补模块、当前背景不适用或确实没有效果。单模块负效应也不能逻辑上排除组合正效应。需要同时区分：

- 固定公共基线上的单独贡献：`B0 + M` 对 `B0`。
- 固定已有组件后的条件贡献：`B_i + M` 对 `B_i`。
- 组合整体是否实用：`B0 + A + B` 对 `B0` 及等预算强基线。
- 交互是否存在：组合变化是否超出单独变化的加和。

在预注册的加性分数尺度上，对同一任务/来源组、同一模型与预算记录四个单元：

| 单元 | A | B |
| --- | --- | --- |
| `Y00` | 关闭 | 关闭 |
| `Y10` | 开启 | 关闭 |
| `Y01` | 关闭 | 开启 |
| `Y11` | 开启 | 开启 |

`interaction(A,B) = Y11 - Y10 - Y01 + Y00`。

例如四个均分是60、60、60、75，组合相对基线提高15，交互也为+15。这只是说明逻辑的虚构例子。实际交互按来源组配对估计并报告区间；“两项单独均不显著、组合显著”本身不能证明交互显著。交互是对选定尺度和背景的陈述，不自动证明因果机制或所有任务上的协同。

联合有用不要求交互为正：两个有益模块相加也可能值得部署；正交互也不保证组合优于基线或满足成本/安全条件。因此 bundle 的效果验收和 interaction 的机制检验分别判定。

## 2. 实现可并行，接入和验收有明确屏障

当前工具会话最多4个活动代理，包括主代理，可采用1个协调/集成者加3个并行实现者，分波覆盖全部模块。会话能力可能变化，正式启动时重新核查。增加子代理不是增加独立训练先验，也不是无限可用模型/CPU配额。

工作树由协调者显式创建并分配绝对路径、分支、允许修改的目录与接口版本；subagent 默认共享工作环境，不能假定调用 spawn 就已隔离。建议分支为 `codex/modular-<module>`，工作树与各自 `work/` 位于项目关联的 E 盘目录。正式创建前读取对应仓库指令和现有 worktree 列表，不复用或修改历史实验工作树。

| 工作流 | 可并行内容 | 必须等待的条件 |
| --- | --- | --- |
| P0 | 两 benchmark adapter、数据托管/访问探针、量尺校准与执行时序的独立代码 | 共同 schema、接口 contract tests、冻结基线与源码来源先一致 |
| 模块实现 | M1–M9 各自实现、单元/契约测试、train-only机制实验；依赖用固定默认实现 | 使用相同 API snapshot；接口改动由协调者单独审阅并同步版本 |
| 单模块实验 | 同一 B0 上独立分支的实验与训练优化可并行 | 各臂同模型/工具/时序；不得把单代理编号与实验臂绑定 |
| 组合构建 | 已接线模块按冻结 activation vector 装配，做跨模块故障检验 | 合并后的确切代码、依赖和环境重新通过集成检查并记录 hash |
| 正式验收 | 已冻结 panel 的任务对可由托管器有界并行派发 | 独立评价包、未用分片、统一预算和配对时序，不提前向开发者泄露结果 |

实现者交付 commit/patch、train-only工件与 `ModuleManifest`；协调者在 integration worktree 合入和验证，不让多个代理共同写公共模块或切换同一工作树的分支。跨仓接线包固定每个 repo 的 commit/dirty patch digest；只提交/集成本次代码，不自动混入其他未提交工作。

Git worktree 只隔离检出文件。它不隔离宿主文件读取、共享 git 对象、cache、模型账户或 Docker daemon。所有优化代理仍须通过训练专用运行环境；标签/验证集不放进任何开发工作树、分支、git历史或可访问索引。分别隔离数据库、日志、输出、端口、依赖环境与缓存。

所有 worker 从中央预算服务领取 model/token/execution lease，统计总调用和资源；不能每个代理独立花一遍全局预算。性能实验需固定资源档、随机化配对次序并记录并发负载；模型API排队和CPU争用不能冒充模块开销。训练数据与资料快照在一波实验内只读，禁止先完成的模块输出自动流入其他在跑实验。

每个新 seam 必须跑真实导出包/宿主/broker集成检查；分支各自测试通过不能替代合并后检查。接口/底座改变后，旧模块实验不是当前包的验证，必须标版本边界并按预注册重测。

## 3. 保留所有模块，分开组件状态与组合状态

`ModuleManifest` 分别记录 `engineering_status / safety_status / standalone_effect / compatibility / requires / conflicts`。单独效果是 positive/negative/inconclusive/not_exercised，不充当兼容性或来源认证。

- 工程和运行安全合格，但单独无增益、负增益或不确定：保留在组合候选池，不自动部署，也不从组合实验移除。
- 工程失败、数据泄漏、违规权限、伪造证据：先修复；不能以“可能存在协同”为由带故障上线。未修复时有关组合保留阻塞记录，不取消研究问题。
- 组合可以通过独立验收后整体晋升，即使其中某组件没有单独效果通过回执。只授权这个精确 bundle、依赖闭包和激活条件，不把其组件分别宣布有效。
- 单模块通过不保证全量组合通过。组合内仍须检验资源竞争、重复上下文、解释冲突和条件误拒。

对象新增 `BundleManifest`：基线 hash、完整组件版本/配置、activation vector、固定背景组件、兼容/依赖闭包、共同资源时序、检索/记忆快照、训练选择来源、部署 digest。禁用模块时保留 P0 最小合法 schema 和宿主安全，不暗中关闭核心契约。

若 B 没有 A 根本无法运行，`A=0,B=1` 是不可行单元，不给它填0分。先判断能否提供对称的最小默认接口；否则将 A 作为固定前置背景，只测 `B|A`，或把 A+B 作为复合因子。没有四个合法单元就不能宣称识别了 A×B；依赖关系不等于实验证明的协同。

P0 封存 `ModuleCompatibilityManifest`：requires/conflicts/shared-core/safety-mandatory、默认替代、每个合法臂的依赖闭包与canonical digest、每个contrast实际变化的组件集合。broker只接受清单中的臂；若开启A同时隐式开启C，结论须标为A+C闭包效应，不能写成A的纯贡献。

组件分别安全不证明组合安全。任何组合进入真实训练或验证实验前，都要在无私有数据的集成夹具上检查capability scope、memory/cache namespace、evidence/subject binding、总预算、FIFO/lease、检索快照和完整回滚；失败记engineering_blocked并修复，不能靠单模块安全回执跳过。

## 4. 全量组合研究路线

9个二元模块在完全无约束时有512种配置。首期不能把“只保留单项赢家”的贪心搜索当作组合研究，也不假定一次全开就解释所有交互。[NIST 全因子实验说明](https://www.itl.nist.gov/div898/handbook/pri/section3/pri333.htm)

| 组合阶段 | 必需研究范围 | 可支持的结论 |
| --- | --- | --- |
| C1 单模块与背景 | 共同B0上的全部合法单模块；必要的固定前置背景；原48项场景 | 单独与条件效应，不能排除其他组合 |
| C2 两模块交互 | 9模块全部36对逐一登记资格；每个合法对跑固定背景的2×2四单元，不按单项成绩筛选 | 该背景/尺度上的两因素交互；不推广到任意背景 |
| C3 机制三模块组 | 至少登记 M2/M3/M5、M4/M5/M6、M1/M4/M7、M3/M6/M9、M7/M8/M9；合法组做2³设计 | 区分主要低阶交互与该组的三阶项；非法单元按约束设计处理 |
| C4 全量与逐一移除 | 最大兼容组合 F，对照B0、强等预算控制及各合法 F−Mi | 组合净收益和完整系统背景下每模块必要性；不能单靠leave-one-out证明纯高阶交互 |
| C5 最终组合验收 | train-only选定并冻结一个目标bundle，以及预注册的控制/消融 | 两 benchmark 新验证族上的质量、安全、成本与范围限定的部署资格 |

“全量”指当前版本的最大合法组合；互斥实现作为同一因子的不同水平或预登记分支，不能强行同时开启。M9 元程序版本是独立子阶段/因子水平，不能混进9个二元模块的512计数。每对/每组三方不具资格时保留 blocked 或 not_identifiable 回执，不当作已检验。

C2/C3/C4 的搜索、配置选择、补充实验及参数优化全部发生在train。训练中可以采用分数因子设计降低运行量，但必须冻结 design matrix、resolution/alias table 与待估计项；交互混叠时做有针对性的增补实验。未经解除混叠不归因，也不能把未覆盖的高阶项说成无效。[NIST 分数因子实验说明](https://www.itl.nist.gov/div898/handbook/pri/section3/pri334.htm)

每个需独立确认的交互在train后预先登记目标、panel与两benchmark验收义务；一次验证panel只包含预注册且有功效/预算支持的有限主要contrast，不把全部组合无界塞入一次验收。其余项目仍保留待确认/数据阻塞状态，不能从训练结果直接升级为已确认。单模块、pair/triple、LOO、两benchmark与重复提交的比较预算统一登记；探索性高阶项不作为晋升依据。

以上保留所有模块与36对研究义务，但不声称穷尽9阶以内全部交互。若要声称覆盖所有合法组合，需实际完整枚举并评价；训练搜索或稀疏性假设不能替代该证据。

## 5. 组合验收与训练/验证隔离

单模块验证之后要有组合验证，且组合选择不能根据单模块验证分数做组合搜索。组合候选池保留全部工程/安全合格版本；候选生成器只使用训练实验数据。若预注册流程允许单模块晋升改变背景，只由托管器落实该固定分支，组合效应报告注明背景版本，使用新的验证组。

修正“每阶段只能评价一个候选”的歧义：**每次只可提交一个冻结的实验设计包 panel，不是只允许运行一个处理臂。** 单模块panel、2×2 panel、2³ panel、全量/消融panel都可包含多个预注册臂。所有臂的代码、参数、任务、顺序随机化、主要对比和统计预算在任何验证结果出来前一起冻结。

同一个冻结panel的各臂应在**相同来源组**上配对，这是估计交互的必要对照；不需要每个臂消耗不同验证样本。整个panel完成后才释放托管报告，分片一次性消耗。它不能用于看分后追加组合、调参数、补样本追显著或选择下一轮赢家。

上述禁选赢家适用于每个组合panel，而不只V_final：lease签发前固定一个拟部署目标bundle（纯机制panel可无部署目标），其他臂只能用于已登记的对比。目标失败时不能改部署同panel的另一臂，即使它分数最高；交互结论与部署决定分别生成。

新设计/新参数/按结果决定的新组合必须回train，并使用新的验证分片。跨模块共享验证结果的 adaptive panel 不属于本协议。托管器记录 joint hypotheses、来源组数、所有比较、失败/缺失和多重检验预算，按组重采样四单元/八单元对比。

`V_final` 验收训练阶段预先指定的目标bundle。其他冻结控制/消融只解释其表现；不能查看 final 结果后挑另一个最高分配置来部署。目标bundle失败或证据不足则保留旧部署；训练侧提出的新目标需要新的独立验收。

组合效果、交互、科学安全、过拒和真实总成本分别报告。成立的正交互不能抵消未授权放行、测量失效、显著质量损失或超预算。运行安全要求组件先合格；科学性能和科学判断安全还必须以完整bundle的新数据结果验收。

## 6. 覆盖、冻结与晋升对象补充

`StageAllocationManifest` 新增 C1–C5，保持原Q1–Q8的48项，不把组合测试计数混入48项覆盖证明。组合试验登记 `pair_id/block_id/full_ablation_id` 与所关联的 Q ids，另外绑定 `panel_digest/factor_levels/fixed_background/feasible_cells/contrast_matrix/alias_table/target_bundle_digest`。

评价器拒绝缺失合法臂、不同背景混用、资源时序漂移、scope/source group不配对、事后删负结果或候选包漂移。非法结构单元预先声明为不可识别，不与模型运行失败混淆。

receipt 标记 `estimand = standalone_at_B0 / conditional_at_parent / joint_bundle / interaction_on_scale / leave_one_out_at_full`，并绑定背景digest和分数尺度。联合效果、相加预期、交互估计、CI与可识别性分开存储；这些不同问题的结果不合并成模块优先级总分。

晋升器消费目标bundle的独立回执并原子切换整个依赖闭包。组件“单独未通过效果”不阻断已通过组合的部署；组件未通过工程/运行安全、bundle未通过独立验收则阻断。回滚恢复整包及其状态视图，而不是逐组件退回一个未经检验的混合配置。

## 7. 数据与本轮交付边界

固定多臂panel共享同一新分片可减少不必要的分片消耗，但不会创造更多独立来源组，也不能解决当前BLADE最多一个潜在新可评分族的问题。保留所有单模块、36对组合及高阶/全量实验；数据不足时继续train侧实现与实验，确认性记录阻塞，不宣称泛化已通过。

初始设计轮（2026-09-12）仅核查工作树、修订设计并检查文档一致性。当时尚未派发实现代理或运行模型实验；后续执行与失败证据按日期保留在实施记录中。
