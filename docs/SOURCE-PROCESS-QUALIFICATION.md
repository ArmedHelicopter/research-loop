# Process qualification and sealed prospective partitions

The 2026-09-13 scope decision permits a testable, bounded access audit and a
conservative partition over observed source relationships. It does not require
proof that a foundation model never encountered public benchmarks in pretraining.
It does not change the old `independent_clean` attestation or any existing split.

`bounded-process-access-audit-v1` starts at the two pinned acquisition receipts
and ends at the audit's UTC timestamp. It binds the unchanged extended inventory,
the subsequent custody metadata receipt, and the explicitly listed controller
attempts and model ledgers. Only packet identity metadata and call/status/token
counts are inspected. Prompt files, model responses, gold, and dynamic task keys
are never exported. Its observation is limited to no target projection observed
in that declared receipt scope. The audit explicitly retains OS-access,
unlogged-history, pretraining, cross-source independence, and upstream data-term
gaps. A scope review commitment is not cryptographic identity authentication.

The new partition is separately named `prospective-observed-family-split-v1`.
The custodian reconstructs membership from verified snapshots; the sealing API
does not accept caller-invented membership or a caller-asserted clean audit.
SciCode's 80 atomic main problems and dependent steps remain one conservative
fallback family because their external reference mapping is absent. SAB joins
exact dataset-tree and source-path equalities and canonical repository matches;
all rows with unmapped repositories join one fallback group, which also joins
any known groups connected by the same observed metadata factors. The existing
canonical graph adds shared scientific artifact/reference closure. A connection
to either old primary source forces that entire group into train.

The shared `ScienceAgentBench.csv` file and SciCode JSONL files are storage
containers. Their byte hashes bind provenance and integrity; they do not imply
all contained records share one scientific dataset. In contrast, equality of an
actual `dataset_folder_tree` declaration is a conservative grouping constraint.
Neither relation establishes absolute scientific independence.

The seed `research-loop-observed-family-split-20260913-v1` and validation fraction
30% are frozen before the actual partition is computed. No seed search or
outcome-based repartition is permitted. Validation is a sealed token allocation,
with no payload projection, lease, or optimizer access granted by this API.
Its only future use is an independently controlled acceptance entry point after
the training candidate and scoring contract are frozen. Operational benchmark
adapters and upstream artifact-specific terms remain separate checks.

DiscoveryBench and BLADE remain the primary benchmarks. This additional scoped
partition does not establish independent validation families for those sources
and does not establish scientific effectiveness.

The repository-metadata supplement separately binds actual official GitHub GET
responses and current repository license metadata. A current repository license
is not an upstream scientific-data license and its revision is not automatically
the revision used by the benchmark. The first supplement accepted bare
`owner/repo/` trailing-slash identifiers that the frozen canonical schema did
not accept, introducing a thirtieth repository token for three unmapped rows.
The request and all original responses remain in the first attempt denominator.
An initial sentinel hypothesis was disproved by fixed-field structural counts;
the additional `n/a` missing-value regression remains useful. The corrected classifier
uses already received response hashes, without another download or any task
inspection; the synthetic sentinel regressions are required before partitioning.

## Actual sealed allocation

The frozen seed produced 164 train and 18 sealed validation records. SciCode's
single 80-record fallback group is train. SAB has 20 train groups containing 84
records and eight validation groups containing 18 records. Its three unmapped
repository rows remain in their shared fallback closure on the validation side.
No observed canonical connection to an old primary source was found; incomplete
publication/artifact coverage means this is not proof of cross-source independence.

The process audit covers five explicitly named solver ledgers: both Q3.1 runs,
both linked-train runs, and the M4/M5 run. They contain 159 succeeded solver calls,
1,743,025 known tokens, and zero incomplete ledger flags. These are historical
solver observations, not new charges and not the total cost of independent
evaluators or other historical activity. The unchanged extended inventory remains
SHA-256 `6959fe024f6468b0fc0bae79ab3d39ff73c0492c6f15659079d178e4b0a212d3`.

The supplement made 53 actual GET attempts. Eight were HTTP 403; ten attempts
were failed or metadata-unresolved in total. After canonical reclassification,
22 of the 29 repositories have received current pins and 19 have received
repository-license declarations. No TLS bypass, paid model call, or follow-up
download was used. The first failed seal attempt stopped at classification
counts; the second stopped at unsupported historical controller schemas. Both
failure receipts remain, and neither wrote a split.

The successful seal was executed at `edd7d6f`. Additional input-binding guards
and a full synthetic pinned-source-to-seal integration test were frozen at
`5a2636e`; the real audit's input bindings were then independently recomputed and
matched without repartitioning. Tests only use synthetic source payloads.

The new API currently provides process audit, conservative grouping, and token
partition sealing. It provides no payload train exporter and no validation lease
or payload export API. Existing train exporters require the old custody split
and cannot consume this new manifest. Connecting a new train-only exporter and
the independently controlled acceptance lease is remaining integration work;
neither can be replaced by writing legacy `independent_clean` flags. The sealed
18 records must remain inaccessible to optimization while that work proceeds.

The exact evidence paths, hashes, scope, counts, and preserved failures are in
`source-process-qualification-verification.json`. This allocation adds no AIRS
tasks: AIRS retains 20 controlled records in 14 local declaration groups, with
upstream artifact/terms binding and a usable evaluation adapter still missing.
DiscoveryBench and BLADE require their own subsequent process/lineage audit and
independent acceptance design; these 18 SAB records do not replace either primary
endpoint.
