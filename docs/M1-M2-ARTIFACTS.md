# M1/M2 逐项产物与历史重放

2026-09-14。此接入覆盖 `RunSession` 内的准入操作，以及该 session 的
`evidence.jsonl`、`claims.jsonl`。统一产物目录保留各模块的实际原始日志。

M1 对每份审查输入、拒绝和准入决定登记独立描述符。M2 的观察器接在
原始日志 fsync 之后，捕获直接 ledger 调用；证据追加/撤回、主张创建、
关系修订、依赖更新、摘要提示、撤回刷新和依赖传播均逐条登记。
每条描述符包含原始事件、当次实际输出、日志内序号、模块启用状态和源码。
模块未启用时，共用基础设施产生的记录保留为 `not_applied`，不冒充模块效果。

主张版本通过 `supersedes` 引用旧版本，`supports`、`refutes`、`depends_on`
引用当时的实际证据或主张版本。`withdraws` 保留被撤回记录；
`withdrawal_observed` 仅表示该刷新时已观察到撤回，不推断每次撤回都具有因果作用。
`checked_by` 连接准入决定和由其产生的证据，不能据此提升科学有效性。
通用 trace 父项仍只是执行顺序，不解释为科学支持。

`verify_evidence_artifacts` 从磁盘重读目录和三份源日志，核对逐项完整性，并按
全局事件顺序调用原 ledger 操作重放。它重新计算证据根身份、主张输出和依赖传播，
因此仅修改数据再重算本地哈希不能绕过语义核验。它也在每个 `model_request`
位置保留经过重放的证据/主张快照，供上下文检查使用；不会用最终状态代替历史状态。
`full_loo_driver.verify_stage` 已实际调用该核验入口。

原日志或目录写入失败会终止 session，禁止后续模型调用。源日志、内存状态和
目录可能已部分推进，不能回写成成功；独立的 `audit-failure.json` 记录失败。
若存储连失败标记也无法写入，保留原异常，由外层阶段回执报告失败。

仍有限制：原 `summary_notice` 只保留摘要文本的哈希，重放可验修订语义，
不能恢复或验证未保留的原文。`retrieval_stage_panel_drivers` 的独立持久化 ledger
尚未接入本 session 观察器。跨目录关系、任意二进制输入、完整源码归档解析和资源
分摊仍按总覆盖清单继续实现。此工程接入不等于所有模块完整覆盖或 benchmark 有效。
