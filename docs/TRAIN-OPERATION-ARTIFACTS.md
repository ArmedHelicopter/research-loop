# TRAIN 操作的产物与读取边界

2026-09-15。此接口覆盖 `train_operations.py` 的 Q6.1、Q6.5、Q6.6 实际宿主，
不是这些问题的科学效果验收。它补在既有 M9 提案/构建审计与后继 solver 之间。

每次宿主操作创建独立 UUID，绑定 TRAIN 任务、冻结计划、实验格、父包、候选、
历史训练配置来源、反馈规则及实际源码。完整审计内容不进入优化器上下文；
solver 仍只读取原有的受限公开投影。跨题历史属于 TRAIN 配置来源，不能作为
当前任务的证据父项或 VAL 授权。

实际日志写入后立即登记事件。数据库初始化、激活、回滚及故障注入后保存逐文件
字节副本；终态再将实际文件与目录逐项对账。每个副本有文件名、内容地址、大小、
阶段及生产源码。已知数据库和部署文件有 M9 归属，其他文件显式保留为 uncovered。
快照父项表示记录顺序，不独自证明因果关系。

`train-operation-receipt-v2` 的宿主签名绑定文件清单及封存目录。消费入口
`_verify_operation` 重读原始日志、字节副本、目录和 seal，再核对以下实际状态：

- Q6.1 的四种越权挑战必须被拒绝，不能由重新计算过的摘要改成 accepted。
- Q6.5 保留反馈预约、原始响应、已知或未知费用，以及固定保护规则选择的包。
- Q6.6 核对 SQLite 活动指针和一次性授权消费、部署完整包与内存、当前/前一副本、
  激活/回滚回执、重复请求拒绝，以及漂移或离线后不产生后继执行。

数据库语义读取使用内存中的原始 SQLite 字节；既有宿主终态核验使用只读连接。
读取器不重建部署宿主、不调用反馈、不激活或修复被审计对象。未知费用不能记作零。
TRAIN staging authorization 仍无法授权生产 ExecutionRuntime。

操作可能已经提交后才抛出异常。此时保留实际终态，包括损坏或部分写入的字节，
并要求此前已记录的正常检查点通过语义核验。失败终态只返回 storage_verified，
operation_validated 和 engineering_verified 均为 false，不提供后继包。
审计存储本身写入失败时保留已有前缀；没有完整封存的前缀不能通过成功读取入口。
