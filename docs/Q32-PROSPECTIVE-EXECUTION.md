# Q3.2 prospective execution phase v1

This is a new train-only entry point, not a rewrite of the historical
`planning_only` driver or its caller-supplied support qualification. The registry's
joint/separate contrast is conditional on M4 being enabled in both arms. Two
benchmarks times two strategies produce four cells. This does not replace the
old eight-cell module ablation or establish a scientific result.

The caller freezes a shared three-hypothesis plan, three pairwise plans, and
three operational numeric measurements before producing any programs. Joint
applies all three measurements to one common plan; separate applies one
measurement to each pairwise plan. Hypothesis definitions and predictions are
identical wherever a branch appears. The caller's plans and measurement meanings
remain unverified scientific inputs. Pairwise allocation is explicit, not inferred
from model wording. No observed support material enters this phase.

Every cell gets exactly three program-production model opportunities, three
Docker execution opportunities, and one final comparison opportunity. The
production slots are new, not silently added to the old budget. Each Docker
uses the same pinned image, timeout, one CPU and 1 GiB memory; all cells for a
task bind the same exported CSV bytes. All three programs, plan IDs, measurement
IDs and input receipts are sealed before the first execution. Runtime failure
consumes its opportunity and retains an unknown observation in the three-row
denominator. Terminal failures retain blocked rows and unused opportunities.

Only actual successful receipt stdout can become a numeric observation. It must
name the exact frozen observable. A read-only verifier replays original event
ordering and request/response/plan/input/program/receipt bindings, even after
an adversary recomputes the hash chain. Range membership is a mechanical endpoint;
it does not call the scientific outcome admission API or claim calibration.
Distinct programs and executions against one CSV are derived measurements of
the same input, not independent datasets or new scientific evidence.

Model-visible material comprises the public task, declared hypotheses and
measurement instructions, then actual measurements/failure facts. Condition
names, custody qualification, arm hashes and controller manifests remain in the
controller trace. Neutral plan handles preserve shared-plan relationships.
P0 blocks unsupported positive/negative conclusions. The final report preserves
scientific_validated=false and programme_complete=false.

Verification: synthetic custody export and real CodexModelPort transport fixture,
real Docker, all four success cells and four execution-failure cells; complete
request-field inspection; early execution, post-freeze plan/input/program swaps,
late/relinked events, malformed stdout, producer failure and unsupported claims.
The old planning and linked chronology tests remain regression checks. No paid
transport, private reference payload, validation export, or scientific scorer is
used. Original RED, frozen source hashes and final reports must be retained.
