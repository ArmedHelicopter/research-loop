# Grok 官方单次执行路径的实际检验

2026-09-14，安装中的 `grok 1.0.13` 已通过一次受限的真实单次调用。
固定输入只要求返回 `{"transport_ok":true}`，未使用 benchmark 数据或验证集。
这证明下述配置下的单次传输可用，还没有把它接成实验用 provider。

## 原始结果

| 独立调用 | 冻结输出上限 | 实际输出 token | 主调用总 token | 工具调用 | 退出/耗时 | 检验结果 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| r1 | 128 | 132 | 1,985 | 0 | 0 / 31.265 秒 | 超出预设输出上限，保留失败 |
| r2 | 512 | 97 | 1,950 | 0 | 0 / 12.609 秒 | 原有流读取器检验通过 |

两次均有三个明确为空的工具清单、一个正常结束事件、一次服务端主调用记录、
匹配的 session ID，以及内容相同的文本 JSON 和结构化 JSON。可用命令仅有五个
内建命令。r2 使用在调用前另行冻结的 512 上限，不改变 r1 的约束或结论。
时延、输出长度和缓存条件不同，不能把两行解释为性能对照实验。

两个主调用的服务端计价分别为 $0.00146404 和 $0.00145792；这是服务端计价，
不等于额外扣款。每次调用前后均重新查询：统一订阅池、编程访问权有效、按量
额度/用量/预付余额全部为零、无自动充值。余额百分比从 98% 到 97% 的变化不能
排除同账户其他活动，也不能用来分摊本次精确费用。初始标题机会的实际用量、
全部机会总计和最终结算仍未知。未提供或使用 API key，未购买或开启付费回退。

## 路径和来源

实际命令使用 `--prompt-file`、`--output-format streaming-json`、`--model grok-4.6`、
一次 agent turn、完整 33 项工具禁用表、显式 agent 定义、系统提示覆盖和独立
home/profile/cwd。API-key 登录通过进程内配置禁用；调用前的 `inspect --json`
实际返回该策略已启用，且没有外部技能、插件、MCP 或项目指令。

运行前先用官方 `grok models` 命令正常刷新了既有登录。该命令输出的最初状态
是 `You are not authenticated.`；不能把它改写为成功登录消息。实际证据是缓存
到期状态从已过期变为未过期，随后同一原生登录的官方账户 GET 返回 200 并通过
身份绑定。这个事实也不足以把全部历史 stdio 超时归因于过期登录。

官方公开源码中的 headless 入口通过进程内 ACP 通道调用 agent；stdio 是另一个
传输入口。本次未改变 stdio 的失败记录或宣称已修复它。
[公开 headless 入口](https://github.com/xai-org/grok-build/blob/bc7f02eddd3d84085849dc19ed216f11c23b0571/crates/codegen/xai-grok-pager/src/headless.rs)。
七个所用公开文件的 Git blob 均与固定公开源码树一致；这不是安装二进制的
可复现构建证明。

账户查询沿用官方 CLI proxy 的只读 GET 路径。直接 `/user?include=subscription`
返回的标签是 `GrokPro`，不伪装为 ACP 的界面标签 `SuperGrok`。实际准入依据
是明确的统一订阅池、剩余额度、访问权、零付费余额/额度及无自动充值，而非
推测套餐名称。它是独立的账户观察模式，不是伪造的原生 ACP 回执。
[官方查询实现](https://github.com/xai-org/grok-build/blob/bc7f02eddd3d84085849dc19ed216f11c23b0571/crates/codegen/xai-grok-shell/src/extensions/billing.rs)。

初版只读查询器错误地把登录页面域名当作 OAuth issuer，在网络请求前被自身
检查拒绝。修正为公开常量 `https://auth.x.ai` 后，三个 GET 均成功；随后原本
照搬界面套餐标签的检查又拒绝了 `GrokPro`。两份拒绝记录保留，不是账号失败。
最终账户检查通过 13 项无网络检查，涵盖非零付费余额、缺字段、空/未知配额、
自动充值、账号错绑和访问权缺失。

## 可审计范围与后续接入

[原件目录](../results/modular-engineering-20260914/grok-headless-readiness-r1/) 保存
49 份原始文件或字节副本，包括两个模型事件流、冻结命令/配置/源代码摘要、
生产脚本、原有流读取器、成功和失败回执及公开源码。两个流已通过原读取器
重新检验，结果与当时回执逐字段一致。12 份私有账户响应的摘要也已重读核验；
含姓名、邮箱及账号身份的用户响应与所有登录凭据均不进入公开目录。

现有四题材料编写器与 TRAIN provider 仍使用自己的 ACP 回执模式。本次脚本
尚未满足这些入口的部署契约，不能把输出包装成 ACP 回执送进去。下一步需要
版本化的 headless 生产入口及独立回执读取器，绑定完整提示、schema、原始响应、
进程身份、来源和账户观察，再接入原有材料校验与签名流程。四个 TRAIN 请求、
36 个材料槽位和后续 180 次评审/评分机会的原有含义不变。

这两次调用不是训练优化、模块/组合效果检验或 VAL 验收；完整实验目标仍未完成。
