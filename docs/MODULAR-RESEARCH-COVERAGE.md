# 原对话八个问题的完整实验覆盖

初始规格日期：2026-09-12。当前工程状态（2026-09-13）：48 项均有执行合同，分为 43 个注册题目驱动和 5 个独立 Q6 训练阶段；这不等于所有题目已完成 benchmark 效果实验。逐次证据与剩余工作见 [实施记录](MODULAR-IMPLEMENTATION-STATUS.md) 和 [本次检查点](MODULAR-CHECKPOINT-20260913-REFERENCE-COMBINATIONS-LINKED.md)。下表保留完整研究规格，不能以工程检查通过替代 `train_measured` 或验证验收。

来源：[研究架构与先验偏置分享对话](https://chatgpt.com/s/t_6aa5249396488191a62ee99332081c77)。本文把对话中的全部八类问题拆成可追踪条目，不把问题优先级用于删减范围。模块边界见 [架构](MODULAR-RESEARCH-ARCHITECTURE.md)，数据与判定见 [实验协议](MODULAR-EXPERIMENT-PROTOCOL.md)。

每个实验 ID 都要记录 `implementation_ref / train_run / frozen_candidate / discovery_receipt / blade_receipt / mechanism_receipt / decision / limitation`。同一模块可支持多项实验，但不能以其中一项通过代替其余条目。状态依次为 designed、implemented、integration_verified、train_measured、candidate_frozen、validation_measured、accepted/rejected/inconclusive；数据或量尺阻塞另记原因，不记完成。

下文各表“主指标”是机制层终点；**每一行最终还须具备两个 benchmark 的分析质量、科学有效性、过拒与成本检查**。数据合格才运行；不合格时对应字段填写托管器签发的 blocked receipt，不能计为该项独立验收完成。P0 将每个ID与实际 scenario/arms/receipt 绑定，不能把一张模块总分回执用来冒充48项都已执行。同一问题的变体可以在同一冻结阶段联合运行，但比较族与统计预算必须预注册。不得把几十个变体当独立新数据、或挑显著的一项报告。

一行涉及多个模块时，先固定背景做单独/条件检验，再按 [必需组合实验](PARALLEL-IMPLEMENTATION-AND-COMBINATION-TESTS.md) 做交互与整体检验；单独无收益者仍保留组合资格。不能一起开启后把提升归给某一模块。原48项全部保留，新增36对兼容性/交互资格登记及三元、全量、移除实验；这些不是可随意重复使用同一验证集的机会。

## Q1. 历史与先验如何可纠正，而不是追求没有偏置

设计对象为相对固定任务分布上的错误恢复与正确保持，不提出无分布条件的普遍最优性。真正有因果意义的历史与无关叙事分别操纵。

| ID / 子问题 | 模块与具体实验 | 主指标与失败条件 |
| --- | --- | --- |
| Q1.1 历史摘要的路径依赖 | M3：同题、同原始证据，配正确/错误/中性摘要；随后给完全相同新证据。对照滚动摘要、等 token 截断、按证据状态重建 | 错误恢复率、正确结论保持率、叙事导致的判断翻转、额外无效执行次数；只缩短文本不算纠偏 |
| Q1.2 显式和隐式依赖传播 | M2+M3：同一上游主张分别仅出现在摘要、已登记依赖中；撤回上游后重建后继上下文 | 受影响后继漏标率、失效解释残留率、有效后继误伤率；无法追踪的摘要断言只能标来源不足 |
| Q1.3 原始证据/主张/假说/摘要混为一体 | M2：保持观测相同，分别重复写成日志、报告、摘要、记忆；对照不去重与根 evidence id 去重 | 独立支持计数、置信/准入变化；重复文字不得增加独立证据 |
| Q1.4 多条独立支持链的部分失效 | M2：构造两条真实独立支持链，撤回一条；另设全部支持失效及只有复制来源两个对照 | 该撤回而未撤回、无依据整树否定、独立有效支持保持；支持关系逐条重审 |
| Q1.5 证据重建式复盘 | M5：只读原始证据/冻结规则先独立裁决，再揭示历史总结；对照先看总结的常规复盘，计算预算相同 | 非证据断言检出、错误改对/正确改错、复核成本；历史与盲判不同不自动认定盲判正确 |
| Q1.6 撤回不依赖替代方案更好 | M1+M2：给定泄漏、计算错误或构念失效证据，操纵是否存在替代理论、旧方案历史最高分 | 无效主张持续被引用率、撤回延迟；新理论另行准入，不因撤回旧理论获得支持 |
| Q1.7 反证、未知与有意义的时间信息 | M3：无关叙事变体与真正改变数据时间/因果顺序的变体分开；有效证据不足时允许 unknown | 无关叙事不敏感、有意义新证据敏感；“永远保持原判断”或“全部unknown”均失败 |

Q1.2 的接线必须从 `ClaimRevision` 触发派生 context cache 失效，并在下一次真实 model payload 中验证；不能只验证依赖图函数返回了 needs_review。

Q2.3/Q2.4 的 caller shadow execution 以冻结程序和命名公开输入的 SHA-256 合约绑定到实际 `ExecutionReceipt`；端口自报摘要不足以通过。模型最终请求只投影执行状态、宿主核验状态和实际准入/未提升状态。完整 M1 处理、双审计材料和独立检查保留在控制器 trace，不能作为 arm、package 或真值线索注入模型。
Q2.1 与 Q4 的 production review drivers 将 arm、control、review journal identity、package 和阶段标签保留在 controller trace。模型请求只接收 opaque cell binding、公共证据及真实产生的 review/admission/prediction 产物或同形空值；不以模型可见开关决定运行行为或验收期望。

## Q3. 竞争假说、FIFO 与并行的区别

| ID / 子问题 | 模块与具体实验 | 主指标与失败条件 |
| --- | --- | --- |
| Q3.1 多假说是否真的有预测张力 | M4：一个研究项内组织机制有效、额外计算、测量偏差三个可检验解释，冻结干预下的不同预测 | 至少有能区分解释的观察映射；只有宽泛零假说、不同标题不算张力 |
| Q3.2 一个多臂实验还是各自找支持 | M4：在同预算下比较共同实验多臂与分别寻找各自支持的实验 | 假说排除/保留校准、独立数据使用量、正确区分成本；选择性证据不得提高主张支持 |
| Q3.3 FIFO 不等于单 worker | M8：固定同一 FIFO 队列与预算，对照1 worker与K workers，原子领取最早可执行项 | 重复领取、漏项、公平性、资源占用、吞吐/墙时；不以预测质量排序替换 FIFO |
| Q3.4 并行先完成结果污染未完成实验 | M8：随机改变完成顺序、有利/不利结果先返回；冻结开始证据快照及归并屏障 | 未完成臂上下文/规则 hash 不变，结果对调度顺序稳定；先完成者不能改全局解释 |
| Q3.5 资源、依赖冲突与恢复 | M8：同 artifact 写冲突、依赖撤回、worker崩溃/超时、租约过期、重复回执 | 并发上限、无双重计费/重复执行、可恢复封存、依赖失效传播；未知运行不得直接重跑 |

M8 先完成按开始快照执行、最后按依赖归并；冲突导致延期是允许结果。真实安全新事件可中断相关臂并记 invalidated，不将其悄悄换成新的实验。

## Q5. 可行性、多样性与想法评价失灵

比较对象必须包含有能力的检索、候选生成、去重与排序基线；对话涉及的想法生成工作本来就不只是一个裸提示。因此增加 agent 数量或增加一次检索本身不是新机制成立的证据，必须通过下面的控制辨别具体增量。

| ID / 子问题 | 模块与具体实验 | 主指标与失败条件 |
| --- | --- | --- |
| Q5.1 可行性分阶段兑现 | M7：同提案比较主观可行性分与分阶段交付：表述→数据依赖→最小运行→区分测量→独立结果 | 每阶段通过/失败原因、提前预报校准、资源浪费；后级资格不由前级自动获得 |
| Q5.2 跑通不等于能区分假说 | M4/M7：正常退出但两解释同预测的实验，对照有负对照且预测可区分的实验 | 可识别性、负对照有效性、工程/科学状态混淆；退出0不作科学主指标 |
| Q5.3 机制/预测去重优于标题去重吗 | M4：文字不同机制相同、文字相似预测相反的提案对；对照标题/向量去重 | 机制重复率、有效方向误合并率、保留预测覆盖；不把措辞差异当研究多样性 |
| Q5.4 评价想法改为选择最有判别力的小实验 | M4/M7：主观综合分选择 vs 预注册不确定性与成本选择下一项有限诊断 | 每预算排除错误解释数、实验后的判断校准、最终任务质量；只改变选择单位，不替换 programme 目标 |
| Q5.5 实际依赖、方法与资源闭合 | M6/M7：可行性结论必须交数据来源、版本、预算、最小产物和负对照，逐项受控缺失 | 依赖缺失检出、首次/最终运行、可复算结论率；“8分可行”不能替代工件 |

Q5.4 只在已领取的一个研究项内部选择诊断/实验臂；外部研究任务队列保持 FIFO，避免违反当前仓库约束。自动生成假说不能生成或准入评价自身的 benchmark 题。

冲突结果触发更强复核而不是自动无效；价值怀疑可进入受限探索。探索上限、宿主安全、证据标准保持独立控制，不能用其中一层的通过替代另一层。

## 全量交付规则

共 **48 项**实验：Q1=7、Q2=7、Q3=5、Q4=5、Q5=5、Q6=6、Q7=6、Q8=7。P0+M1–M9 是实现分组；Q6.3 另立 M9 的元程序改进阶段。分组共享代码不减少48项研究义务。

每次模块交付时先核对该模块关联的全部 ID：没有接线证明、训练结果、独立验证或明确失败/阻塞状态的条目不得被打勾。一个模块被实验否决后，保持可测试的插件和结果；依赖它的后续问题通过最小接口/隔离实验继续研究，不因此删除后续问题，也不把未验收候选混入默认基线。

若 benchmark 不覆盖某能力或独立样本不足，记录 `not_exercised` 或 `blocked_insufficient_independent_groups`，并指出需要的派生序列/独立数据。不得以方便的门控单测、评分变高、代码能跑或增加文档代替原问题。所有结论说明所测任务、版本、预算和数据范围。
