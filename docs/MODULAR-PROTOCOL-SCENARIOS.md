# Goal and protocol fixture scenarios

Q2.6 now runs controlled secondary-endpoint success, maintenance completion and
post-hoc pivot proposals through the real frozen objective and final gate. The
next model request retains the original task and success rule; the proposed
change is a separate, unauthorized proposal. Returned callback output is what
the gate actually evaluates. An honest `unknown` answer remains permitted.
Semantic relevance of an endpoint and legitimate new-version authorization
still require independent review; this fixture does not decide them by text.

Q2.7 omits execution or audit, proposes an illegal state, or removes the lock
from a separately archived and rechained replay. Missing execution and audit
reach a blocked runtime decision. A journal without the lock is refused at
receipt verification; the original complete journal remains unchanged.

`verify_protocol_trace` checks calls, frozen objectives, execution allocation,
audit lineage and terminal outcome consistency in addition to hash chaining.
The panel receipt verifier calls this check before admitting a runtime receipt.
Adversarial replays remove steps and recompute the chain, so a passing checksum
cannot stand in for having executed the protocol. Blocked and incomplete runs
remain inspectable; they do not become successful measurements.

This is an engineering fixture for both public benchmark task adapters. It
does not run actual benchmark analyses, authenticate audit signatures, or
establish scientific truth. The independent audit and scoring services retain
those responsibilities. It leaves Q2.2 semantic scorer calibration and all
required paired training/validation efficacy measurements outstanding.
