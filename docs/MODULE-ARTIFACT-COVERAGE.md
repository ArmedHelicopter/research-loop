`module=None, coverage=uncovered` 的通用 trace 事件也保留原始内容、来源和封存校验。
它们可以用来发现尚未登记的输出，不能自动算成模块覆盖。
目前 `parents` 只表示同目录父项；按事件顺序建立的关系不得解释成经过验证的因果依赖。
state 配置桥接在有类型和宿主校验的 payload 中保存外部封存来源，不把它伪装成
同目录 parent 或跨题支持证据，具体边界见 [TRAIN 配置关联](STATE-TRAIN-CONFIGURATION-ARTIFACTS.md)。

完整性核验重读 `artifacts.jsonl`、持久化 seal 和阶段 `receipt.json`，检查序号、
摘要链、任务及运行绑定、内容、源码、父项和 trace 对账。阶段回执另绑定文件清单。
目录写入失败时，已有 trace 可能比目录多；失败阶段保留该缺口和独立失败回执，
不会伪造一份完整成功目录。`artifact-journal-failure.json` 特指恢复日志也写入失败；
其他失败通过阶段回执中的状态和原因记录，不能以缺少该文件推定运行成功。
