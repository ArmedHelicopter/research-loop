# 产物审计覆盖清单

2026-09-14。此清单区分实际接入的输出和仍需补齐的接口。
每模块出现一条 `covered` 记录不表示该模块的全部输出都已覆盖。
`covered` 是一条描述符有明确模块归属，完整覆盖须另与实际输出清单对账。

| 模块/边界 | 当前实际接入 | 待补齐的逐产物覆盖 |
| --- | --- | --- |
| P0 | 运行任务锁、独立 run ID、冻结计划摘要 | 数据划分、全部资源及读取权限的独立登记 |
| M1、M2 | 实际 lineage transition 及准入原始回执引用 | 每项准入决定、证据/主张、修订和撤回关系 |
| M3 | transition；实际模型上下文保存在 `model_request` trace | 实际上下文、筛选与压缩结果、引用及预算的专门描述符 |
| M4 | 观察前冻结的预测 | 预测更新、评分与适用范围 |
| M5 | 评审封存与揭盲结果 | 盲审输入、每份提交及分歧记录的独立登记 |
| M6 | 检索结果 | 查询、源版本、原始/筛选结果及每个引用的明确关系 |
| M7 | 探索选择及阶段回执 | 许可、探针、程序、失败输出的完整链 |
| M8 | 阶段回执 | 队列、任务依赖、并行计划、尝试及合并回执 |
| M9 | history 中实际生成的候选；C5 选择结果有独立组合登记与重验接口 | 训练选择、部署/回滚的统一目录接入 |
| 生命周期 | 未启用、失败、拒绝、阻塞、撤回、替代等状态可以显式记录 | 替代/撤回关系、重试编号和下游待复核标记 |
| 跨主体关系 | 任务证据与 TRAIN 配置使用有不同契约；C5 独立登记保留九组件和全部 TRAIN 选择来源 | 通用跨目录、跨主体关系图；当前台账拒绝外部控制边 |
| 原始内容与来源 | 规范 JSON 内容、摘要及大小，实际生产代码路径/摘要/大小；检查源码 ZIP 原件另行归档 | 任意二进制产物存储、历史源码快照解析、环境与模型调用的逐产物桥接 |
| 成本 | 明确区分未知与已知；未知不能填零 | 各类实际资源及单位的逐产物分摊，审计自身开销的对照实验 |

`module=None, coverage=uncovered` 的通用 trace 事件也保留原始内容、来源和封存校验。
它们可以用来发现尚未登记的输出，不能自动算成模块覆盖。
目前 `parents` 只表示同目录父项；按事件顺序建立的关系不得解释成经过验证的因果依赖。

完整性核验重读 `artifacts.jsonl`、持久化 seal 和阶段 `receipt.json`，检查序号、
摘要链、任务及运行绑定、内容、源码、父项和 trace 对账。阶段回执另绑定文件清单。
目录写入失败时，已有 trace 可能比目录多；失败阶段保留该缺口和独立失败回执，
不会伪造一份完整成功目录。`artifact-journal-failure.json` 特指恢复日志也写入失败；
其他失败通过阶段回执中的状态和原因记录，不能以缺少该文件推定运行成功。

TRAIN/VAL 的描述符规则不等于操作系统权限隔离。优化器只能拿到 TRAIN 的数据、
索引及产物视图，实际读取隔离由 custody broker 和独立存储落实；VAL 只供验收。
成功记录和哈希校验不授予科学有效性、独立验收或部署权限。

工程验收原件会按具体源代码版本列在实施状态中；真实 benchmark 效果、全部
问题/组合实验、完整 C5 和 VAL 验收仍分别保留自己的验收要求。
