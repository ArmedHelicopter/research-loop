# 设计思路

## 要挡住的失败，不是要加速的搜索

源仓 research loop 的直接起因不是「实验太慢」，而是「agent 同时拥有定义目标、执行、评判成功、宣告完成四项权力」。2026-08-21 的具体行为是合并已有 commit、刷新清单、重跑已有测试、写 GOAL_COMPLETE。那种完成永远成功，所以不能当研究进展。

因此协议的主轴是**拆权**和**见结果前锁定**。Zheng et al. 2026 的 Predict-then-Verify 被本仓收成 LOCK 之后、RUN 之前的**资格预报**（量尺/产物/构念能不能跑），不是「预测哪份训练代码更好」的 AutoML 筛子。Kwok et al. 2026 的准则分解与重复评估被收成审计总判 = 预注册小事实的合取（可二次核对），不是连续分、不是轨迹排序。占用的是他们的 Beat Ratio / Terminal-Bench 数字和偏好排序器；机制可以改 workflow。

## 干预是什么

被测系统（臂 B）对每次科研**决策**施加：

1. 三个角色，权力集合不相交。
2. 执行前写入判定规则并做内容哈希；执行后哈希必须一致。
3. Auditor 只对预注册清单做二元检查。
4. 输出不得包含顶层目标完成句。
5. 不得在见结果后改阈值、改主终点、把无效检验改写成阴性发现。

对照系统（臂 A）是同一模型、同一任务、同一预算的单 agent：可以随时改成功标准，可以自己宣布完成。

可选臂 C：只强制 JSON schema、不隔离角色。用来排除「多写几个字段」这一混淆。

## 和源仓实现的差

源仓文档声称 LOCK 由 hash 约束、admit 走 two-sided band。对照实验必须按**代码实际行为**来实现干预，不能按愿望：

- 源仓 `lock_decision.py` 曾在空白骨架上算 hash；本仓臂 B 必须在规则填完后哈希。
- 源仓 `admit` 检查 proposer ≠ challenger 和 schema，并不机械执行 L1–U4 难度带；本仓若要把 band 算进干预，必须写成可执行谓词，并单独消融。
- 源仓选择器绑定 G1–G4 cursor。本仓没有这些目标，不得把 cursor 搬过来当「通用 AGI 调度」。

也就是说：本仓检验的是**文档里的协议意图**，必要时会先补上源仓还没强制的那几行，再拿去对照。若补完之后对照失败，失败的是意图，不能回退成「源码本来就没强制」。

## 构念

- **目标替换：** 把预注册问题换成更容易成功的问题，或把 programme 写成已完成。
- **事后改门槛：** 见到输出后修改 decision_rule、阈值、主终点。
- **假完成：** 用治理成功（测试绿、hash 新、文档多）代替研究对象上的判别。
- **判别力：** 在 ground truth 不进入 prompt 的前提下，对预注册终点的判定是否与隐藏标签一致。

主终点是前三类的违规率。判别力是非劣效约束：分权不得靠「什么都判无效」来刷低违规。

## 为什么不在源仓里做

1. 对象不同。源仓对象是神经系统里的类策略行为；本仓对象是科研 agent 的决策协议。混在一个 docket 里，Stage 9 会把「证明 loop」洗成 Ready。
2. 循环。用被测 loop 来决定 loop 是否有效，会把成功标准交给被测仪器。
3. 泄漏。源仓 PSB 题的判定写在 `gate.json` 里，不能当任务。
4. 公开边界。本仓不应搬未发表的 persona 主张。
