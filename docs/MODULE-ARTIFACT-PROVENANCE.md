# 每个模块产物的审计与溯源契约

2026-09-14。适用于 P0、M1–M9、全部问题与单模块/组合实验，以及独立验收。
本文定义验收要求；实现和实测覆盖由实施状态记录说明，不能由本文推定完成。

每个模块对外产出可解析、不可原地修改的产物引用。统一目录记录来源关系，
模块仍通过各自接口执行；目录不决定模块算法、实验选择或科学结论。
同样的记录机制适用于对照臂，记录开销单独测量并计入资源对比。

## 产物与运行记录

一个产物由不可变内容、描述符和追加式运行事件组成。内容可以是规范 JSON，
也可以是源文件/执行回执/模型结果的原始字节；摘要必须能解析回实际内容。
文件位置不是身份，内容摘要也不单独证明谁产生了它。

描述符必须包含以下已知信息，缺失信息显式为未知：

| 字段 | 要求 |
| --- | --- |
| 身份 | 内容摘要、字节数、编码、类型、模式版本、存储引用 |
| 生产者 | 模块与接口版本、实际源码快照摘要、配置/提示模板/运行环境引用 |
| 输入 | 数据集版本、任务与来源族、划分版本、TRAIN/VAL 域、输入产物引用 |
| 执行 | 实验/运行/尝试 ID、冻结协议与组合配置、模型部署与可用的调用回执 |
| 依赖 | 父产物引用及关系类型，支持多个父节点；不得仅按时间相邻猜测语义依赖 |
| 状态 | 已生成、失败、拒绝、阻塞、撤回、被替代；未启用和未覆盖必须明确 |
| 检查 | 执行、完整性、任务绑定、科学验收等检查各自的回执引用与适用范围 |
| 成本 | 实际可观测资源、单位及归属；未知用量与未知结算不得填成零 |

每次重试产生新尝试，替代产生新节点和 `supersedes` 边，撤回追加事件。
失败输出、未执行原因和不完整输出均保留。科学结论引用独立验收回执，
不得从“成功退出”“文件存在”或“哈希一致”自动推导科学有效。

## 分模块覆盖

| 模块 | 至少需要注册的输出 |
| --- | --- |
| P0 | 冻结任务、数据划分、基线、资源与实验协议、权限边界 |
| M1 准入 | 审查输入、接纳/拒绝决定及理由、绑定任务的审查回执 |
| M2 证据与主张 | 证据根、主张、修订/撤回记录及其支持或反驳关系 |
| M3 上下文 | 实际呈现的上下文、筛选/压缩结果、引用来源和预算 |
| M4 预测 | 观察结果前冻结的预测、更新与评分适用范围 |
| M5 独立评审 | 盲审输入、各评审提交、揭盲与分歧记录 |
| M6 检索 | 查询、检索源版本、原始结果、筛选结果与引用 |
| M7 探索 | 分配与许可、探针选择、实验程序、探索结果和失败 |
| M8 调度 | 队列/依赖/并行计划、任务尝试、执行与合并回执 |
| M9 TRAIN 改进 | 训练历史、候选、训练选择结果、九组件版本和部署/回滚引用 |

模块自己的 JSONL、SQLite 或执行回执仍是相应事实的原始记录；桥接器注册实际
记录内容及引用。未知事件进入覆盖缺口清单，不能因为存在统一日志就宣称全部覆盖。
输出清单必须与实际事件和文件清单对账，模块未启用时不得登记为该模块已运行。

## 依赖图与组合实验

同一产物可以有多个上游来源。以下边有不同语义，验证器分别检查：

- `consumes` / `derived_from`：实际输入和派生产物。
- `supports` / `refutes`：支持或反驳同一任务/研究对象的证据；禁止对象替换。
- `trained_on` / `selected_using`：跨训练题的学习与候选选择来源，只允许 TRAIN。
- `configured_by`：后续任务使用冻结组件或组合配置；配置保留全部 TRAIN 来源。
  在独立验收流程允许使用该配置时，VAL 任务可以消费它，但不得反向进入训练选择。
- `executed_by` / `checked_by`：执行者与检查回执，不等同科学支持。
- `supersedes` / `withdraws`：生命周期记录，原产物保持可查。

跨训练题学习合法不代表旧题证据能支持新题结论。组合运行须明确记录各模块
组件版本及共享输入，不能将 A+B 的结果重新标成 A 或 B 的单模块结果。
单模块阴性保留在图中，仍执行预定配对、高阶组合与消融；禁止按单模块结果
删除既定组合。一个上游产物被撤回后，沿依赖关系标记受影响结果待复核，
不删除历史、不自动把全部下游判为科学失败。

## 封存、权限与完整性

模块运行仅追加记录。journal 包含序号、前项摘要和描述符摘要；重新打开时严格
验证模式、身份、顺序、重复项与父项。核验必须重读磁盘，不能只检查内存缓存。
阶段结束后固定记录数、最终摘要及实际文件清单，并由独立的阶段回执绑定。
这样才能检测尾部删除；未封存阶段只能报告当前前缀可验证，不能报告完整性已证明。
目录不能证明恶意宿主重写所有原始记录与所有外部锚点后仍未篡改。

trace 与目录分步写入中途失败时，运行标记为不完整，由对账识别缺口。
封存之后不得继续追加该阶段目录。后续评分与验收使用新阶段，引用旧封存锚点。
模型/外部进程调用前固定输入；调用后核对实际产物，源文件改变则原冻结检查失效。

TRAIN 和 VAL 使用独立存储根、索引和读取权限。优化器只能接收 TRAIN 视图，
不能仅依靠描述符上的可见性布尔值隐藏已经可读取的 VAL 文件或索引。
独立验收器读取封存候选与 VAL，结果只用于验收；所有后续优化仍仅使用 TRAIN。
全链路审计由独立授权的审计入口完成，敏感数据和凭据不复制进公共目录。

## 验收与交付

必须以真实入口验证至少一次覆盖 M1–M9 的 history→target 执行、一次失败路径、
一次组合和一次替代/撤回。工程检查可使用合成模型响应与实际 Docker；
真实 benchmark 效果另按冻结实验协议验证，不相互替代。

故障检查包括实际 payload 篡改、伪造源码绑定、缺失父项、记录重排/重复/截断、
trace 与目录不一致、跨对象证据替换、VAL 及其索引泄漏，以及未知成本冒充零。
交付包含源代码、契约、冻结版本的检查原件、覆盖清单和可从最终结果反向追踪的图。

实际接入范围与未接入项见[产物审计覆盖清单](MODULE-ARTIFACT-COVERAGE.md)，
具体版本的执行证据见[实施状态](MODULAR-IMPLEMENTATION-STATUS.md)。

普通评分另有[实际交换留存契约](SCORER-EXCHANGE-OBSERVATIONS.md)：在解析前保留
启动握手及逐格请求/返回文本，并在首次及缓存返回前核对原始字节、持久成功日志
和签名评分。[已通过的冻结检查与原件](../results/modular-engineering-20260915/scorer-exchange-observations-r1/README.md)
覆盖两个主 benchmark；中性观察不会被登记成某个算法模块已运行的证据。

最新可检查的真实例子是[一次 Grok 4.6 TRAIN 调用及独立重放](../results/modular-engineering-20260915/grok130-normal-train-control-r2/README.md)：
请求、固定部署、原始返回、账本和消费结果均有精确引用，非凭据原件私有保留。
它只有一次真实调用，不能当作单模块或组合有效性结论。

P0 另提供[独立 custody 快照审计入口](P0-CUSTODY-AUDIT-SNAPSHOTS.md)，面向审计器
而非优化器。它核验预先保留的字节锚点、当前划分和显式提供的签名租约回执，不伪造
混合数据域的单一 TRAIN 身份，也不把缺失回执当成已经签发或已经验收。

可调用的[M2 类型化关系读取器](M2-TYPED-PROJECTION.md)从封存目录和原 ledger
重放得到撤回目标及明确的后续观察，结果保留读取器源码摘要和完整性范围。
[评分封存消费端观察](SCORER-FINALIZATION-OBSERVATIONS.md)则保留解析、验签前的
请求与返回文本，以及认证或拒绝终态。各自证据范围须按对应契约解读。

可直接查看[一次实际评审运行的产物依赖图](../results/modular-engineering-20260915/review-lineage-r1/README.md)：
从最终输出反向定位冻结输入、各次调用的原始返回、评审事件和预测封存。
图中 32 个节点、87 条消费关系来自已落盘的合成工程用例，完整摘要和原件引用
一并保留；这提供一个可检查的实例，不代表其余模块或跨目录关系已全部覆盖。

另有[覆盖 M1–M9 相应阶段的 history→target 实例](../results/modular-engineering-20260915/c5-headless-runtime-probe-r1/README.md)：
212 个描述符、311 条目录父引用和一条明确的构建绑定，可定位原始文件与行号。
M8 在 history 未启用、M9 仅在 history 构建、撤回记录及 70 个未归属模块的
trace 均按原样保留。九份生产源码副本与描述符摘要匹配，2,304 个非凭据原件
已归档并逐成员读回。该工程探针只执行一个构建和一个目标，使用 11 次合成
solver 调用，没有 evaluator 调用；源码仅有运行后匹配快照。它不构成完整
C5、全部逐产物覆盖或真实效果证据，早期缺失的源码原件也没有被补造。

[逐条追溯核对](../results/modular-engineering-20260915/c5-provenance-followup-r1/README.md)
补充了 70 条通用事件的明细，以及从构建请求和终态回查 M9 产物的字段索引。
目录中真实存在的引用、字段相等关系和经验证的语义消费分别记录，避免把默认
附着到最近事件的父引用解释成因果依赖或完整模块覆盖。

另有[真实 TRAIN 评审的追溯实例](../results/modular-engineering-20260915/actual-headless-review-r1/README.md)：
157 个节点、260 条来源关系绑定原始材料、冻结请求、11 次实际模型调用和最终
消费者回执。独立内存重放得到完全一致的回执及日志；其中 10 次消费通过、
1 次因后置账户查询不完整而拒绝。失败原件和已知用量保留，评分调用为零。
这证明该次消费路径可回查，不等同所有模块覆盖或科学效果验收。

该轮 257 份原始运行文件另有私有保留副本；ZIP 成员与原件逐项核对，原件
字节和时间戳保持不变，登录凭据及私钥不在复制范围内。定位与核验结果见
[私有原件保留回执](../results/modular-engineering-20260915/headless-account-recovery-r1/private-r1-retention-verification.json)。
它补充持久保存，不把运行目录副本当作包含全部外部数据、配置和源码的独立复现包。

训练实验还提供[独立的 headless Grok 产物契约](GROK-HEADLESS-TRAIN-PROVIDER.md)：
从冻结公共请求、实际原始返回，经 provider 封存，追踪到模块或组合单元消费的
确切调用编号。M4/M5 的 v5 入口保留完整四臂，评分之后仍重读原件；末次评分
返回后发现替换，也保留历史评分并拒绝有效对比。原始输出存在但后置检查失败、
未知用量、损坏回执等情况，均保留失败分母。工程执行与真实 benchmark 效果
仍分别记录，实际覆盖和冻结检查版本以覆盖清单为准。

该 TRAIN 接入已通过 [91 项冻结检查](../results/modular-engineering-20260915/headless-train-provider-r1/README.md)，
包含实际单模块入口、M4/M5 四臂、末次评分后的原件替换拒绝及旧 ACP 回归。
后续 [实际评审 r2](../results/modular-engineering-20260915/actual-headless-review-r2/README.md)
另外保留 85 次真实 MAIN、一次 MAIN 前拒绝及 25 次诊断评分，并完成结果与
日志的独立内存重放。前者是工程检查，后者是相关 TRAIN 诊断，均不推定全部
模块效果、正式校准或 VAL 验收已完成。

M4/M5 的显式 v6 入口随后补齐私有评分端最终封存：八份评分返回后再重读
评分器原件，绑定实际调用、评分回执和完整格数；之后重复读取仍走子进程
核验。失败保留历史评分，最终对比不获准使用。实现与 40 项冻结检查、成功
和失败原件见 [评分终结检查](../results/modular-engineering-20260915/headless-evaluator-controller-r1/README.md)。
其他控制器及跨模块目录关系继续按覆盖清单逐项跟踪，不能由该入口推定全部完成。
