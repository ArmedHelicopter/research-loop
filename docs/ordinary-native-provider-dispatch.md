# Ordinary native TRAIN dispatch

The new explicitly versioned envelopes admit an exact `GrokTrainProvider` whose
configuration equals the frozen native descriptor. Legacy Codex envelopes keep
their old meanings. M4/M5 v4, C4, and build/phase routes have separate owners.

The ordinary route inventory contains 43 singleton registry entries and 30
combination IDs in 11 controller families. Singleton configurations freeze the
union of their actual driver slots and each variant's allocated call count;
linked benchmark mode adds its two solver slots to the same owned cell span.
All combination families bind runtime events to the original per-cell call IDs
before scoring and again after the independent scorer returns. Reporting replays
originals after contrasts and captures accounting with that final gate. Returned
score receipts remain historical evidence if current provenance becomes invalid;
eligible score counts become zero and eligible contrasts become unavailable.

The separate Q3.2 execution route uses source configuration v3 and compilation
v2. Four task/variant cell IDs each freeze a fresh original native descriptor:
four MAIN calls, three executions, native lifetime 60 seconds, retry zero,
included-only billing, no top-up, empty tools, model 4.6, 262144 prompt bytes,
8192 requested output tokens for each program slot and 2048 for final, with
131072 observed MAIN tokens per cell. TITLE and total settlement stay unknown.
An unknown MAIN or original provenance fault stops the entire run; fresh ports
for later cells cannot bypass this gate. All four cells and 12 measurements
remain in the denominator, with unattempted rows explicitly blocked.

Q3.2 retains its original hash-chained runtime trace. A separate projection
receipt binds each original request to the deterministic public request and its
response digest, then binds that derived event view to the exact native call
span. It never rewrites the original trace to make digests agree. Actual Docker
measurement receipts are independently replayed by the existing Q3.2 verifier.
Its native runtime result has a new schema and uses the native compiled budget;
the old 180-second Codex budget and old result contracts remain unchanged.

Synthetic default-entry checks use executable peers only below the final OS
spawn seam, with real Docker and scorer processes where applicable. Such checks
establish bounded engineering behavior, not model capability or scientific
effectiveness. C5 still requires the separately frozen selection and validation
work; this provider port does not resolve that limitation or open VAL.

Q3.2 final panel/result rows use v2 after the global provenance gate. Each row
retains `historical_cell_score_eligible`, while current `score_eligible` is false
for every row if any provider's final replay fails. Original per-cell v1 files
are preserved unchanged. The native source-attempt status follows the inner
panel status; the legacy source-attempt contract is unchanged.
