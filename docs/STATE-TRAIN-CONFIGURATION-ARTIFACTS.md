目标调用开始前，驱动器先校验原候选 barrier，再把所用候选的来源登记到
目标自己的产物目录。每条 `configured_by` 关联保存原构建配方、候选内容及摘要、
全部 TRAIN manifest、构建回执摘要、原目录的摘要及封存记录，以及目标 cell、
任务锁和协议摘要。目标 trace 在模型调用之前绑定这条产物描述符。

构建通过原组合和臂定位，不能仅按候选摘要查找：不同构建可以产生相同候选。
M9 关闭时仍保留实际固定配置的来源，模块状态为 `not_applied`。配置被使用与
M9 是否启用分别记录。跨训练题的配置使用不构成对新题结论的支持证据。

正常返回的目标阶段封存整个目录。`verify_state_configuration` 从调用者提供的
原 barrier 定位源目录，重读源候选、原目录与封存、目标目录及 trace，并核对
登记发生在调用之前。记录内的路径用于定位说明；读取器不跟随其中被替换的路径
去打开其他数据。此入口只接受 TRAIN，其他阶段的 VAL 配置使用需要自己的授权
和隔离适配器，不能据这条记录取得 VAL 访问权限。

独立调用该读取器验证的是来源完整性及精确绑定；完整阶段认证仍由实际宿主的
barrier/执行/评分读取器完成。它不执行构建、补写缺失封存、改变评分或授予科学
有效性、独立验收及部署权限。这个适配器也不开放通用目录的外部 `control_sources`。
其他宿主、九组件组合配置、跨目录撤回传播和通用中断前缀验收仍需要逐项接入。
