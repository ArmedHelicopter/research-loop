# 材料资格评估的产物契约

材料资格评估是模块启用前的共享 TRAIN 前置步骤。它同时服务普通对照、M1
准入及其他状态/检索组合，不能因为留下记录就把 M1 标为启用。实际生产入口是
`DualMaterialVerifier.qualify`；`AdmissionMaterialVerifier` 另要求主体一致、
评估结构正确及两方结论一致。

## 产物与消费关口

原有 JSON 回执路径和返回摘要保留。每个回执增加同级
`<回执文件名>.artifacts/`，使用独立尝试 ID，保存请求、材料、运行单元、
配置权威及生产源码的绑定。两次评估分别记录预约、返回、检查结果和成本状态；
原回执每次覆盖写入后立即保存原始字节，因此四个中间版本都可复查。

资格评估者报错、拒绝或返回无效内容时，仍保留原协议的两次机会。存储本身
失败则停止后续调用，单独保存已有回执、日志、字节和部分封存；不能把一次
存储错误解释成评估者的一个负面结论，再继续调用。失败记录只公开错误类型，
原始异常保留在异常因果链中，不进入宿主的公开错误文本。

`replay` 必须同时通过产物读取器和原有签名/主体/成本核验。独立读取器核对
请求与调用方预期、唯一尝试、严格事件结构与顺序、完整文件清单、内容摘要、
每个中间版本及成功终态。两份完整但互相矛盾的 Admission 评估会封存为拒绝。
未知成本仍为未知；宿主原有的成本门槛继续阻止后续工作。

实际 C4/C5 宿主在创建模型会话前调用上述入口；成功阶段验收时再次读取。
其他共用资格评估器的状态、检索、探索、调度及构建宿主也使用同一方法。
仅查看失败存储的 `inspect` 不调用评估者，不授予资格或后续执行权。

## 读取与来源边界

读取器在文件内容读取前拒绝链接、junction 及相关祖先路径。当前代码的成功
重读要求保留的三份资格评估/准入源码与受信当前源码一致；历史记录应通过其
原冻结源码版本重读。它不是任意历史运行环境的自动复建。

合法 FrozenRecord 返回保留完整规范内容。无类型的 JSON 安全返回可以保留
有界内容；不能安全序列化的对象只保留类型与明确的覆盖缺口，不执行其
`repr`/`str`，也不声称已保存其全部内部状态。

本地摘要与配置权威签名证明受检字节和主体绑定；它们不证明两个来源科学上
独立，也不授予 VAL、科学有效性或部署权限。此接口不覆盖任意评估回调另写的
文件、远程服务内部日志或完整资源分摊。

## 验证范围

新增检查包括实际生产/重读、四次回执写入的部分失败、失败记录再次写坏、
原始返回已保存后报错、Admission 拒绝、重新计算摘要的语义篡改，以及实际
C5→C4 宿主的 history→target 和模型调用前拒绝。测试固定使用合成 TRAIN
响应；实际宿主检查执行 Docker。具体冻结版本、通过数量和原件位置以
[实施状态](MODULAR-IMPLEMENTATION-STATUS.md) 的本次完成记录为准。

全模块输出覆盖、跨目录生命周期、真实模型/组合效果与 VAL 验收仍分别验收；
不能用这些工程检查替代原有完整实验目标。
