# Frozen combination scorer process

`CombinationScorerProcessClient` runs the existing independent adapted scorer
across the explicit UTF-8 stdio boundary. The current concrete controller
supports the complete M4/M5 training factorial: both core benchmarks, four arms,
one shared-session mechanism and solve per cell, and one scorer opportunity per
cell. Other catalogue combinations still require their actual module executors.

Before export or a solver call, the client performs a fresh nonce handshake.
The worker reports bindings derived from its actual service: the complete frozen
panel, scorer configuration, opaque reference handles, and execution/scorer key
hashes. Drift is rejected before reservations or evaluator calls. The handshake
does not disclose reference text or key bytes and does not spend a scoring call.
The controller also compares the exported, compiled panel with the worker's
frozen panel before executing it.

The signed candidate transaction uses the existing durable client and worker
journals. Completed identical requests can be recovered; changed candidates and
unknown transactions retain their original refusal semantics. No automatic
retry is introduced. The worker uses the real combination scoring service and
evaluator model port with the protected reference resolver; it does not score
its own execution claims.
