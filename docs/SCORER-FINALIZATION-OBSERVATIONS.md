# 评分器终结响应的消费端观察

2026-09-15。该接口补充共用评分进程的产物追溯：一次终结请求发出前记录请求，
读到响应后先保存内容，再执行 JSON、请求绑定和签名核验。原始评分器封存与
客户端实际收到的内容各自保留，不能用前者代替后者。

## 记录内容与读取

观察位于评分客户端原 journal 旁的 `.headless-evaluator-client.jsonl` 文件。
每次读取，包括对同一封存的重复读取，使用新 attempt ID，并保留原 nonce、
panel、评分配置、提供方配置和生产源码摘要。事件按以下次序追加：

1. `requested`：实际交给 Python 文本输出包装器的请求字符串及其 UTF-8 摘要。
2. `response_received`：文本输入包装器返回的字符串、UTF-8 字节数及摘要。
3. `authenticated` 或 `rejected`：通过验签的封存摘要，或拒绝类型与已收到内容的摘要。

这是文本层观察。Windows 文本管道可能转换换行符，这些摘要不声称对应原始
管道字节；解码或读取失败时也不补造未收到的文本。空返回、畸形 JSON、错误
nonce 和无效签名仍保留当时实际读到的字符串。

每条外层记录绑定序号、前项摘要和事件摘要。只读入口
`read_headless_client_observations` 检查链、尝试顺序、原文摘要和终态引用。
不完整尝试可作为前缀检查，不能用作已完成的消费回执。后续追加先重新读取
记录；同一客户端另持有最后一次写入的锚点，删除完整尾部也会在下次读取前拒绝。

记录不是签名评分证据，也不是阶段全量封存。跨进程审计需要另外保留的终态
锚点或归档清单，才能发现删除整个终态尝试；宿主重写全部记录与外部锚点的
情况不在该本地完整性保证内。`authenticated` 仅表示当前签名封存已通过既有
校验，完整 panel 与科学效果仍由相应消费者另行判定。

## 失败与访问边界

首次观察写失败会阻止请求发出。响应观察或终态观察写失败会阻止返回有效
封存，留下可检查的失败前缀。若连拒绝记录都写失败，向上保留原核验异常，
并明确报告观察存储失败；不会以第二次写成功追认第一次消费成功。

重复读取仍向评分子进程重新请求，重新验证当前原件。观察日志没有引入
本地成功缓存，不改变原签名、配置、调用顺序或用量门槛。

日志与原评分 journal 处于同一访问域。畸形响应可能包含意外内容，因此实际
运行原文按私有证据保存；公开材料引用经核对的摘要和必要元数据。优化侧仍
只访问 TRAIN，VAL 及其评分结果不能进入训练选择。

## 与模块目录的关系

这些观察提供生产源码、panel、配置、nonce、尝试和内容摘要，可用于精确定位。
admission/prediction/exploration 的 native-v4 消费端会把已重新读取、链核对的
终结事件投影到每个实际 TRAIN task identity 的独立 catalogue。投影只含原文
摘要、字节数和冻结绑定，不复制请求或响应文本；它们标记为 `module=null`、
`coverage=uncovered`，没有 parent 边，也不授予评分、封存或科学资格。跨任务
panel 因此不会被伪造为一个单一主体产物。该桥接目前只覆盖这一个 admission
入口；普通逐格评分、启动握手、解码前字节及其他进程入口仍需各自的原件留存
适配。观察相邻不代表模块实际消费，跨模块关系仍由明确入口及语义读取器核验，
见[模块产物契约](MODULE-ARTIFACT-PROVENANCE.md)。

此文定义实现边界；具体冻结版本、成功与失败检查见实施状态中的证据链接。
