# Prospective Q7.3–Q7.6 implementation contract

This plan extends the frozen Q7.1/Q7.2 implementation without changing its tree,
the common registry/controller, P0, old custody state, or any validation lease.
All inputs and runs are train-only. The first executable checks will use public
synthetic data and actual restricted Docker executions with the existing pinned
image and isolated Python environment.

The minimum complete grid is 88 cells across both primary benchmark adapters:
16 Q7.3 cells, 24 Q7.4 cells, 32 Q7.5 cells and 16 Q7.6 cells. Registered variant
names only select caller-frozen material; the implementation must not derive
expected success or scientific state from a variant name.

## Q7.3: finite exploration ratios

Freeze four prospective ratios and the same four execution opportunities for
every arm. M7 reserves the ratio's integer diagnostic allocation and corresponding
main-task allocation; the control uses its frozen baseline allocation. The
selected public diagnostic/main programs actually execute. Caller verification
checks complete receipts and input/program bytes before returning effective
diagnostic, waste, unknown and main-progress observations. Exit status does not
define diagnostic effectiveness. All requests, allocated and unused opportunity
counts, observed costs and unknown costs stay in the denominator.

A separate train-only selector requires every predeclared ratio's complete,
source-bound receipts at the same budget and source version. It selects by a
predeclared ordering of effective diagnostics, waste and main-task displacement,
or returns unresolved when required observations are missing. No ratio is
claimed naturally correct, and the selector refuses validation provenance before
reading outcomes.

## Q7.4: instrument repair

Run the old instrument and a follow-up instrument under a two-execution budget.
M7 may select the frozen repair candidate; the control repeats the frozen
original. Trusted checks distinguish byte/measurement execution from construct
validity and bind the repair to the prior instrument and observation. M1 records
`InstrumentRepair`, preserves old raw evidence and enforces that only a new
qualified execution can be admitted after repair. The old-evidence probe submits
the unchanged old execution identifier to fixed P0.

Do not manufacture an initial valid audit for a known invalid instrument merely
to demonstrate later withdrawal. Existing admitted evidence may be invalidated
when genuine new source-bound evidence requires it; initially invalid evidence
remains unadmitted and cannot be revived by a successful new instrument.

## Q7.5: four distinct dimensions

Execute and independently check observations for valid-known, novel-refuted,
temporarily infeasible and easy-valid cases. M1 exposes the independently
verified validity/support/novelty/investment state; its control retains its own
unguided judgement under fixed P0. M2 creates and revises separate observation
and novelty claims from admitted observation roots and verified prior-art
evidence. Refuting novelty must not delete or deactivate valid measurement
observations. Pending feasibility must not be converted to scientific refutation.

## Q7.6: engineering contracts and scientific review

Keep byte/type/source/permission checks separate from construct/theory relevance.
Each cell performs a real bounded observation and an actual semantic model review
with equal review opportunity. M5 seals an evidence-first review before revealing
the earlier assessment; the control reviews with that earlier assessment visible.
The independent caller port checks the frozen construct/measurement contract
against actual observations; reviewer acceptance and contract success cannot
replace that scientific check. Preserve disagreement and unknown judgements.

## Shared safety and evidence

Validate every available candidate's exact public input bytes before model or
verifier I/O. Legitimate hard missing resources/authorization remain typed blocked
cells. Recheck chosen inputs at execution and before observation verification.
Give the trusted port complete execution receipts and exact program/CSV bytes;
keep those host details and private observation documents out of model requests.
Persist every reservation before I/O, raw/partial response before validation,
and measured/unknown costs without converting unknown to zero. Return the final
candidate unchanged to `RunSession.finish`; no blanket unknown result policy.
