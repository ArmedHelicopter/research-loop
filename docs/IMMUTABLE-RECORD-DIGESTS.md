# 不可变记录的摘要复用

2026-09-14。此改动降低重复摘要计算的开销，不缓存文件完整性或实验验收决定。

`FrozenRecord.content_hash` 对 4096 至 524288 个字符的普通字符串保留最多
16 个计算结果，以完整的当前字符串作为键。缓存未命中时仍执行原有的
`digest(json.loads(encoded))`。较小、较大以及子类记录走原来的读取路径。
键的字符数和条数有界；这不等于整个进程内存或审计总开销已经测量。

构造器仍检查规范 JSON 对象，`data()` 仍返回新的可修改副本。记录内容变化
产生不同键；即使绕过冻结属性保护，也不会按旧对象身份复用旧摘要。子类的
`data()` 覆盖保留原有语义。缓存既不保留文件路径或权限决定，也不延长 C5 的
临时验证租约；文件、源代码、封存、任务和 TRAIN 绑定继续由原读取器重检。
这不提供对任意进程内代码篡改的防护。

耗时 480.047 秒，706 个源码/文档文件前后一致。检查包含摘要语义与容量边界、
标签隔离、目录与原始源码校验、C5 协议/面板/选择/租约、实际完整模块及普通
对照的 history→target 执行，以及失败写入、P0 数据包和参考答案桥接的拒绝路径。
测试中的重复 ZIP 成员警告来自故意构造的拒绝样例。

公共目录，共 6 个目录和 418 条描述符。私有评分存储、密钥、完整划分和 VAL
索引不进入该归档。归档读取确认存储及源码绑定，不宣称完整历史宿主语义重放。

另对原冻结工程计划和协议做了交替次序的局部计时，重复摘要与原算法结果

模型收益、总资源成本或审计开销的完整 A/B 结果。
