# research-loop-validity

本仓库研究一件事：把科研 agent 的「提案 / 锁定后执行 / 二元审计」分权，并禁止执行者在见到结果后改判定规则，是否比单 agent 循环更少出现目标替换、事后改门槛和假完成，同时不降低对预注册终点的判别力。

它**不是** policy-signature 的替代品，也**不是** AI4Agent AGI 项目。
`policy-signature` 的 programme 句仍由那边的测试 hash 锁定；本仓库不改那句话，也不继承 G1–G4。

当前状态：**协议已从一次真实失败中抽出，有效性未经对照检验。**
在对照完成前，本仓库的任何 README、脚本或演示都不得被读成方法论文结果。

## 为什么要单独开仓

`policy-signature` 里的 research loop 是在 2026-08-21 失败之后装上的控制：当时一个 agent 合并已有 commit、刷新 hash、重跑已有测试套，并宣告 programme 完成。分权、LOCK-before-RUN、Stage 9 只提出候选、auditor 只做二元小事实，都是对那次失败的结构性回应。

控制可以在有失败记录之后立刻使用，就像事故后的操作规程。
**把控制当成已经证明能提高证据效度的科学主张，则是另一件事。**

未验证的治理一旦当真理机器用，危害比不用更大：

- 它会给无效结果盖「已审计」的章（Exp10 那种单位不可比的闭环，可能被当成阴性结果而不是撤回）。
- 它会用关条目、过门禁、写规则来替代研究对象上的进展（2026-08-21/22 大约 2400 行治理、零行实验）。
- 它会让后续所有 G1–G4 闭合都条件依赖于一套未检验的仪器。

因此有效性主张必须离开原 programme，单独定义任务、对照和证伪器。本仓的对象是协议，不是人格接口，也不是 MLE-bench 上哪份训练代码更好。

Zheng et al. ACL 2026（*Can We Predict Before Executing Machine Learning Agents?*）已经占据「执行前预测哪套 ML 方案更好」。本仓不重复那条线，也不用预测分数替换 FIFO 来给实验排序。要检验的是：分权是否降低**科研决策**上的目标替换，不是搜索加速。

## 双轨，而不是停掉原研究

| 仓库 | 角色 | 停用条件 |
| --- | --- | --- |
| `policy-signature` | 继续用 loop 当**控制**（挡住已知的假完成）。G1–G4 / X 评估器仍按那边 docket 推进。 | 不因本仓尚未出数字而停。 |
| 本仓库 | 把同一套协议当**被测对象**。主终点是协议违规率，不是发现新科学。 | 对照若证伪，本仓主张撤回；原仓可把 loop 降级为「未验证控制」并记录。 |

本仓**禁止**用被测 loop 来准入「loop 是否有效」这个结论。成功标准在 [`docs/SPEC.md`](docs/SPEC.md) 里预注册，由人类锁定；本仓不设 Stage 9 后继生成器。

## 设计思路（被测协议）

从 `policy-signature` 抽出的是机制，不是 G1–G4 内容。完整操作说明见 [`docs/DESIGN.md`](docs/DESIGN.md)。

1. **三角色分权。** Proposer 不能执行、不能自评、不能自准入。Executor 不能在见结果后改判定规则，不能宣告顶层目标完成。Auditor 只检查预注册的小事实，裁决只有 valid / invalid，不能把 stop 改成 proceed。
2. **LOCK-before-RUN。** 判定规则、接受标准、最小证伪器必须在读输出前承诺。正确实现是：规则填完后再做内容哈希，审计时核对。源仓目前的 `lock_decision.py` **尚未**做到这一点；本仓实验必须把这条实现缺陷当成干预的一部分，而不是假定源码已经强制 LOCK。
3. **Two-sided band 只用于命题准入，不用于质量排序。** 太易（已有工件可答）或太难（超出当前能力与预算）则拒。线内 FIFO。禁止用模型对「哪个实验更值得跑」打分来改变执行顺序。
4. **提案 ≠ 执行权。** 局部反思只能产生 `proposed`。独立 challenger 才能 admit。
5. **状态词分开。** `closed_negative`、`corrected`、`withdrawn` 不是失败讳饰。无效检验必须撤回，不能收窄成阴性发现。

这些条款是**待检验的干预**，不是已证明的定律。

## 一句问题和最小对照

> 在科研决策任务上，把提案 / 锁定后执行 / 二元审计分给不同 agent，并禁止见结果后改规则，是否比单 agent 循环更少出现目标替换、事后改门槛和假完成，同时不降低对预注册终点的判别力？

臂、数据、终点、证伪规则见 [`docs/SPEC.md`](docs/SPEC.md)。没有这组对照，本仓不构成方法论文。

## 现在不承诺的

- 可发顶会、已有 SOTA、提高科学发现率、通向 AGI。
- 源仓 PSB 上的任何准确率（现有 runner 存在从产物中读取判定的循环，不能当基线）。
- 「LOCK 已由 hash 强制」或「two-sided band 已由 admit 机械执行」——以源仓代码为准，两者都还没有落到可审计的强制点。
- 用本仓存在来暗示 `policy-signature` 的 programme 已完成或被取代。
